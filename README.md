# نظام الموارد البشرية — الحضور والانصراف والإجازات (متكامل مع بصمة ZKTeco)

نظام كامل يعمل فعلياً: خادم **FastAPI + SQLite** وواجهة عربية (RTL) بدون أي أطر عمل خارجية،
مع تكامل حقيقي مع أجهزة البصمة **ZKTeco** بطريقتين: السحب المباشر عبر المنفذ `4370`،
والدفع اللحظي عبر بروتوكول **ADMS/iclock**.

## المزايا

- **الحضور والانصراف**: استيراد البصمات من الأجهزة، احتساب الحضور والتأخير والخروج المبكر
  والوقت الإضافي وساعات العمل، ودعم الورديات الليلية التي تعبر منتصف الليل.
- **آلة حالات ذكية**: معنى البصمة يُحدَّد بحالة الموظف (خارج العمل / داخل العمل / في استراحة)
  لا بترتيبها — حضور، بدء استراحة، عودة، أو انصراف — مع **عدد استراحات بلا حد** في الشفت،
  ومدة كل استراحة على حدة، وتنبيه الإدارة عند التجاوز أو بقاء الاستراحة مفتوحة.
- **سياسات الحضور والاستراحة**: افتراضية للنظام، وأخرى خاصة بكل فرع أو إدارة أو وردية.
- **الورديات**: أوقات دوام، دقائق سماح للدخول والخروج، استراحة، وأيام عمل لكل وردية.
- **الإجازات**: أنواع إجازات قابلة للتخصيص، أرصدة سنوية، احتساب الأيام مع استثناء العطل
  الأسبوعية والرسمية، دورة اعتماد (تقديم ← اعتماد/رفض ← إلغاء مع إرجاع الرصيد)، ومرفقات.
- **العطل الرسمية** وتأثيرها التلقائي على كشوف الحضور واحتساب الإجازات.
- **الصلاحيات**: مدير نظام / موارد بشرية / مدير إدارة (يرى ويعتمد فريقه) / موظف (يرى نفسه فقط).
  واجهة الموظف مختصرة عمداً: لوحة مؤشراته الشخصية، حضوره وبصماته، «إجازاتي» (رصيده وطلباته
  وتقديم طلب جديد)، مخالفاته، قسائم رواتبه، ووثائقه — بلا كشوف الآخرين ولا أجهزة البصمة.
- **التقارير**: لوحة مؤشرات، كشف يومي، كشف موظف لفترة، ملخص شهري، تقرير استثناءات،
  وتصدير CSV لكل ما سبق (يفتح مباشرة في Excel بترميز UTF-8).
- **إدارة الأجهزة**: اختبار الاتصال، مزامنة يدوية أو تلقائية، قراءة مستخدمي الجهاز واستيرادهم
  كموظفين، إرسال موظف إلى الجهاز، ضبط ساعة الجهاز، ومسح سجلاته بعد الاستيراد.
- **الحضور الذاتي من التطبيق مقيّداً بالموقع (Geofencing)**: الموظف يسجّل حضوره وانصرافه من
  جواله، ولا تُقبل البصمة إلا إذا كان داخل نطاق موقع عمل معتمد.
- **بصمة يدوية**: إدخال يدوي من الموارد البشرية عند نسيان الموظف البصم.
- **المخالفات والجزاءات**: أنواع مخالفات بسلّم جزاءات تصاعدي حسب التكرار (إنذار ← خصم نسبة من
  أجر يوم ← خصم أيام ← إيقاف/فصل)، مع إقرار الموظف أو تظلّمه، واعتماد الموارد البشرية،
  وخصم تلقائي في مسير الرواتب.
- **مشتريات الموظفين**: فواتير المتجر أو المطعم تُسجَّل على الموظف وتُخصم من راتب شهرها.
- **طلب «نسيت البصمة»**: الموظف يطلب تسجيل بصمة فائتة، والاعتماد يسجّلها ويعيد احتساب يومه.
- **راتبي حتى اليوم**: استحقاق تناسبي من بداية الشهر مع الخصومات الواقعة حتى تاريخه.
- **مسير الرواتب**: احتساب شهري من الحضور والإجازات والمخالفات (خصم غياب وتأخير وإجازات بلا راتب
  وخصومات المخالفات + بدل العمل الإضافي)، مع تعديلات يدوية واعتماد وقسائم للموظفين وتصدير CSV.
- **الإشعارات**: داخل النظام (جرس بعدّاد) + بريد إلكتروني اختياري + ويب هوك لأي بوابة واتساب/تلجرام.
- **وثائق الموظفين**: إقامة وجواز وعقد وغيرها مع تنبيهات قبل الانتهاء.
- **استيراد جماعي** للموظفين من Excel أو CSV بقالب جاهز.
- **سجل تدقيق** لكل إجراء حسّاس (من فعل ماذا ومتى)، وتعديل أي بصمة أو حذفها يتطلب سبباً
  ويُحفظ معه القيمة القديمة والجديدة — والحذف ناعم لا يمحو السجل من قاعدة البيانات.
- **ربط جوجل شيت**: كل بصمة وإجازة ومخالفة وقسيمة راتب تنزل تلقائياً في ملف Google Sheets
  عبر Apps Script — بدون حساب Google Cloud ولا مفاتيح، مع صندوق إرسال يعيد المحاولة عند انقطاع الشبكة.
- **نسخ احتياطي**: زر تنزيل نسخة كاملة (قاعدة البيانات + المرفقات) من داخل النظام،
  ورفع تلقائي يومي إلى جوجل درايف عبر rclone.
- **تطبيق قابل للتثبيت (PWA)**: يعمل كأيقونة على جوال الموظف مع أيقونة ومظهر تطبيق مستقل.

## التشغيل السريع

```bash
git clone <رابط المستودع> && cd 123
./run.sh --demo          # يثبّت المتطلبات، ينشئ القاعدة، ويعبّئ بيانات تجريبية
# أو بدون بيانات تجريبية:
./run.sh
```

ثم افتح: <http://localhost:8000>  — وتوثيق الـ API التفاعلي على `/docs`.

## ربط جهاز البصمة ZKTeco

يدعم النظام الأجهزة التي تتكلم بروتوكول ZKTeco القياسي (iClock، K40، F18، MB360، uFace،
SpeedFace وغيرها). **شرط أساسي:** رقم الموظف في النظام = رقم المستخدم (PIN) في الجهاز.

### 1) وضع السحب (Pull) — الخادم يتصل بالجهاز

1. من الجهاز: `Comm ← Ethernet` واضبط عنوان IP ثابتاً (مثال `192.168.1.201`).
2. تأكد أن المنفذ `4370` مفتوح وأن الخادم في نفس الشبكة (أو يصل إليها عبر VPN).
3. في النظام: **أجهزة البصمة ← إضافة جهاز** ← الوضع «سحب» + IP + المنفذ + كلمة مرور الاتصال
   (Comm Key، افتراضياً `0`).
4. اضغط **اختبار** للتأكد من الاتصال، ثم **مزامنة** لسحب البصمات.
5. للمزامنة التلقائية: `HR_AUTO_SYNC_MINUTES=10` قبل تشغيل الخادم.

### 2) وضع الدفع (Push / ADMS) — الجهاز يرسل البصمة لحظياً

1. من الجهاز: `Comm ← Cloud Server / ADMS`.
2. `Server Address` = عنوان هذا الخادم، `Server Port` = منفذ التطبيق (`8000` افتراضياً).
3. احفظ وأعد تشغيل الجهاز؛ سيبدأ الاتصال بالمسار `/iclock/` وسيظهر تلقائياً في قائمة الأجهزة
   بعد أول اتصال (يمكنك بعدها إعادة تسميته وتحديد موقعه).

المسارات المنفَّذة من بروتوكول ADMS:
`GET /iclock/cdata` (المصافحة)، `POST /iclock/cdata?table=ATTLOG` (استقبال البصمات)،
`GET /iclock/getrequest` (سحب الأوامر المعلّقة)، `POST /iclock/devicecmd` (نتيجة الأمر)،
`GET /iclock/ping`.

> هذه المسارات لا تتطلب توكن لأن الأجهزة لا تدعمه؛ التمييز يتم بالرقم التسلسلي (SN).
> شغّل النظام داخل الشبكة الداخلية، ولا تعرّض مسار `/iclock/` للإنترنت مباشرة إلا خلف
> بوابة/جدار ناري يسمح بعناوين أجهزتك فقط.

### 3) الوضع التجريبي

جهاز بوضع «تجريبي» يولّد بصمات واقعية (تأخير/غياب/إضافي) لتجربة النظام كاملاً بدون عتاد.

## الحضور الذاتي من التطبيق مع التحقق من الموقع (Geofencing)

يستطيع الموظف تسجيل حضوره/انصرافه من التطبيق نفسه، **بشرط أن يكون داخل موقع العمل**:

1. **الإعدادات ← مواقع العمل والبصم الذاتي ← إضافة موقع**: أدخل اسم الموقع والنطاق المسموح
   بالأمتار (افتراضياً 150 م). اضغط **«📍 التقاط موقعي الحالي»** وأنت داخل المقر لتعبئة
   الإحداثيات تلقائياً، أو انسخها من خرائط Google (ضغط مطوّل على المكان).
2. اختيارياً: اربط كل موظف بموقع محدد من بطاقة الموظف (حقل «موقع العمل»). الموظف غير المرتبط
   بموقع يُقبل بصمه من أي موقع معتمد؛ والمرتبط بموقع لا يُقبل منه إلا من ذلك الموقع.
3. الموظف يفتح النظام على جواله ← **لوحة المؤشرات ← «تسجيل حضور / انصراف»**، فيطلب المتصفح
   إذن الموقع، ويتحقق الخادم من المسافة قبل قبول البصمة. زر **«التحقق من موقعي»** يعرض
   المسافة الحالية قبل التسجيل.

**ما الذي يرفضه النظام؟** البصم خارج النطاق (مع ذكر أقرب موقع والمسافة)، أو بدون إذن الموقع،
أو بدقة تحديد ضعيفة تتجاوز الحد المسموح (افتراضياً 150 م).

**ما الذي يُحفظ مع كل بصمة ذاتية؟** الإحداثيات، دقة التحديد، الموقع المطابق، والمسافة عنه —
وتظهر في «سجل البصمات» مع رابط لعرض النقطة على الخريطة.

**الإعدادات المتاحة** (الإعدادات ← مواقع العمل والبصم الذاتي):

| الإعداد | الوصف |
|---|---|
| السماح بالبصم من التطبيق | تعطيل/تفعيل الميزة كلياً |
| إلزام التواجد داخل موقع العمل | عند تعطيله يُقبل البصم من أي مكان (يبقى الموقع مسجلاً للمراجعة) |
| أقصى هامش خطأ للموقع | الحد الأعلى المقبول لدقة GPS بالأمتار |

> **متطلب تقني:** متصفحات الجوال لا تمنح صلاحية الموقع إلا عبر **HTTPS** (أو `localhost` أثناء
> التجربة)، لذا شغّل النظام خلف Nginx بشهادة SSL قبل اعتماد هذه الميزة على أجهزة الموظفين.

> **حدود الميزة بصراحة:** إحداثيات المتصفح يمكن تزييفها بتطبيقات Mock Location على أجهزة
> مُروَّتة. لذلك يبقى جهاز البصمة هو المصدر الأدق، ويُنصح باستخدام البصم الذاتي للمواقع
> الميدانية أو العمل خارج المقر، مع الاعتماد على تخزين الإحداثيات والمسافة لمراجعة أي حالة
> مشبوهة. الحد الأدنى لدقة التحديد يمنع أغلب الحالات العشوائية غير المتعمدة.

## آلة حالات الحضور والاستراحات

معنى البصمة يُحدَّد بـ**حالة الموظف الآن** لا بترتيب البصمة. الحالات ثلاث، وتتغيّر
مباشرة بعد كل بصمة مقبولة:

| الحالة قبل | البصمة تعني | الحالة بعد |
|---|---|---|
| خارج العمل | `CLOCK_IN` — حضور | داخل العمل |
| داخل العمل (أثناء الوردية) | `BREAK_START` — بدء استراحة | في استراحة |
| داخل العمل (ضمن وقت الانصراف) | `CLOCK_OUT` — انصراف | خارج العمل |
| في استراحة | `BREAK_END` — عودة من الاستراحة | داخل العمل |

فلا تُفهم البصمة الثانية استراحةً لأنها الثانية، ولا الرابعة انصرافاً لأنها الرابعة.
**الانصراف وحده له قاعدته**: لا يُحتسب إلا ضمن «وقت السماح بالانصراف» قبل نهاية الوردية
(٣٠ دقيقة افتراضياً)، حتى لا يتحوّل خروج الاستراحة إلى انصراف نهائي. والعودة من الاستراحة
تُقبل دائماً مهما تأخرت.

**عدد الاستراحات في اليوم بلا حد** ما لم تحدّده السياسة. مثال يوم كامل:

```
08:00 حضور → 10:00 بدء استراحة → 10:15 عودة (15 د)
             12:30 بدء استراحة → 12:45 عودة (15 د)
             15:00 بدء استراحة → 15:10 عودة (10 د)   إجمالي الاستراحة 40 دقيقة
17:00 انصراف
المدة في المقر 9:00 · ساعات العمل الفعلية 8:20
```

**ساعات العمل الفعلية = الانصراف − الحضور − إجمالي الاستراحات** (ويمكن تعطيل الخصم من السياسة).

### الأحداث: سجل لا يُحذف ولا يُخترع

كل بصمة تُنتج **حدثاً** يحمل: معرّف الموظف واسمه ورقمه، الفرع، الجهاز، التاريخ والوقت،
نوع الحدث (`CLOCK_IN` / `BREAK_START` / `BREAK_END` / `CLOCK_OUT`)، **الحالة قبل الحدث
والحالة بعده**، مصدر التسجيل، الوردية، ووقت استلام النظام للبصمة. الأحداث مرتّبة زمنياً،
وتُعرض بالضغط على خانة «استراحة» في كشف اليوم.

الأحداث والاستراحات سجلات **مُشتقّة**: تُبنى من البصمات الخام في كل احتساب، فتبقى مطابقة
لها مهما وصلت بصمة متأخرة أو صُحِّحت لاحقاً. **البصمة الخام لا تُحذف ولا تُستبدل أبداً.**

### لا غياب قبل بداية الدوام

الموظف الذي لم يبدأ دوامه بعد لا يُكتب **غائباً**: تبقى حالة يومه «لم يحن بعد» حتى تبدأ
ورديته (بعد دقائق السماح). فالفترة المسائية التي تبدأ ٤ عصراً تظل «لم يحن بعد» طوال
الصباح بدل أن تظهر غياباً كاذباً في الكشف واللوحة.

### الحالات غير الطبيعية

- **استراحة بلا عودة** → تظهر «استراحة مفتوحة» ويصل تنبيه للإدارة.
- **انتهت الوردية والاستراحة مفتوحة** → حالة اليوم **«تحتاج مراجعة»**، والنظام **لا يخترع
  وقت عودة** ولا وقت انصراف.
- **بصمات مكررة من خطأ الجهاز** → تُهمَل البصمة المكررة خلال المدة المضبوطة
  (`Debounce`، ١٠–٣٠ ثانية عادةً)، وتبقى في القاعدة دون أن تُغيّر الحالة.

### الاستراحة بلا عودة: خصم نصف يوم

من بدأ استراحة ولم يعد حتى نهاية الوردية: يومه **«تحتاج مراجعة»**، ويُخصم عنه **نصف يوم**
من الراتب (النسبة قابلة للضبط من `open_break_deduction_days`: ٠٫٥ = نصف يوم، ١ = يوم كامل،
٠ = بلا خصم ومراجعة يدوية فقط). ويظهر الخصم في القسيمة وجدول الرواتب باسم
«استراحة بلا عودة».

### تجاوز وقت الاستراحة

لا يمنع النظام الموظف من تسجيل العودة إطلاقاً. عند التجاوز:

1. **تنبيه للإدارة**: «الموظف تجاوز وقت البريك المسموح بـ ١٤ دقيقة».
2. **تنبيه للموظف نفسه** على جواله (قابل للتعطيل).
3. **مخالفة تلقائية** باسم «تجاوز وقت الاستراحة» عند بلوغ الحد المضبوط (١٥ دقيقة افتراضياً)،
   تُسجَّل بحالة **بانتظار إقرار الموظف** فله أن يقرّ أو يتظلّم، ولا تُخصم من راتبه إلا بعد
   اعتماد الموارد البشرية، وجزاؤها يتصاعد مع التكرار كبقية المخالفات.

كل ذلك مرة واحدة لكل يوم مهما تكرر الاحتساب، ويظهر في كشف اليوم وفي لوحة «الحالة الآن».
الضبط من **الإعدادات ← سياسة الحضور والاستراحة ← عند تجاوز وقت الاستراحة**.

### لا استراحة قرب نهاية الدوام

داخل «وقت السماح بالانصراف» (٣٠ دقيقة قبل النهاية افتراضياً) **لا وجود للاستراحة**: أي بصمة
فيه تُفهم انصرافاً، وزر «بدء استراحة» يختفي من شاشة الموظف، وضغطه يُرفض برسالة واضحة.

### موظفون لا يأخذون استراحة

في بطاقة الموظف حقل **الاستراحة**. باختيار «لا يأخذ استراحة»:

- لا تُخصم استراحة الوردية الثابتة من ساعاته — فمن يعمل تسع ساعات متصلة تُحتسب له كاملة.
- وإن سجّل استراحة رغم ذلك فهي تجاوز من أول دقيقة بعد دقائق السماح.

### السياسات

**الإعدادات ← سياسة الحضور والاستراحة**. القابل للضبط: مدة الاستراحة المسموحة يومياً،
دقائق السماح، حدّ عدد الاستراحات (٠ = بلا حد)، الحد الأعلى لإجمالي وقت الاستراحة، خصم
الاستراحة من ساعات العمل من عدمه، وقت السماح بالانصراف، سياسة الخروج المبكر، سياسة التأخير،
ومدة تجاهل البصمات المكررة.

ولكل **فرع أو إدارة أو وردية** سياسة خاصة تغلب الافتراضية، والحقول المتروكة فارغة تُورَّث
من الأعم. الترتيب: الوردية ← الإدارة ← الفرع ← الافتراضية.

### التقارير

لكل موظف ولكل يوم: وقت الحضور، وقت الانصراف، **إجمالي مدة وجوده في المقر**، إجمالي وقت
الاستراحة، **عدد الاستراحات ومدة كل واحدة**، التجاوز في الاستراحة، ساعات العمل الفعلية،
التأخير، الخروج المبكر، والوقت الإضافي — في الكشف وفي تصدير CSV.

### شاشة الموظف

الشاشة الرئيسية مبنية على تصور المنشأة:

1. **ترويسة العلامة**: شعار المنشأة واسمها، وجرس الإشعارات بعدّاد، وحرف الموظف.
2. **تحية باسمه** وتاريخ اليوم بالعربية.
3. **بطاقة الحالة الهادئة**: نقطة ملوّنة + «أنت الآن داخل العمل / في استراحة / خارج العمل»
   + «منذ ٧:٤٢ ص»، بخلفية خضراء للعمل وكهرمانية للاستراحة ورمادية خارجه.
4. **بطاقتا أرقام**: «مدة العمل اليوم» (عدّاد حيّ يتحدّث كل نصف دقيقة) و«عدد مرات الحضور».
5. **زر كبير واحد** يتغيّر بحالته، وزر ثانٍ أخف للانصراف.
6. **أربع بطاقات وصول سريع**: طلباتي (بعدّاد) · حضوري · الإشعارات (بعدّاد) · جدولي.
7. **آخر الحركات**: آخر ست حركات بأيقونة ملوّنة لكل نوع (حضور أخضر، استراحة كهرمانية،
   عودة تركوازية، انصراف أحمر) مع الوقت والتاريخ والفرع.
8. **راتبي حتى اليوم** و**دوام اليوم** و**جدول الأسبوع**.

والشريط السفلي: **الرئيسية — الإشعارات — الطلبات — المزيد — حسابي**، و«المزيد» يجمع
مخالفاتي ورواتبي وسلفي ومشترياتي ووثائقي وجدولي وبياناتي وتسجيل الخروج.

وتفصيل الحالات:

- **داخل العمل**: «أنت الآن داخل العمل» مع وقت بداية العمل، وزرّان: بدء استراحة وتسجيل انصراف
  (يتقدّم الانصراف تلقائياً قرب نهاية الوردية).
- **في استراحة**: «أنت الآن في استراحة» مع وقت بدايتها والمدة الجارية المحدَّثة، وزر واحد:
  إنهاء الاستراحة.
- **خارج العمل**: «أنت الآن خارج العمل» مع وقت آخر انصراف.

ولوحة الإدارة فيها بطاقة **«الحالة الآن»**: من داخل العمل، ومن في استراحة، ومن خارج العمل،
مع تمييز التجاوزات والاستراحات المفتوحة، وتتحدّث كل نصف دقيقة.

### تعديل البصمات وسجل التدقيق

تعديل أي بصمة أو حذفها **يتطلب سبباً**، ويُسجَّل في سجل التدقيق: من عدّل، ومتى، والقيمة
القديمة، والقيمة الجديدة، والسبب. والحذف **حذف ناعم**: السجل يبقى في قاعدة البيانات
ويُستبعد من الاحتساب — فلا يُمحى سجل حضور نهائياً بلا أثر.

## راتبي حتى اليوم (الاستحقاق التناسبي)

في شاشة الموظف بطاقة **«راتبي حتى اليوم»** تجيب عن سؤاله المباشر: راتبي ١٠٠٠ ريال واليوم
العاشر — كم استحققت؟

```
أجر اليوم      = 1000 ÷ 30 = 33.33 ريال
المستحق حتى اليوم = 33.33 × 10 = 333.33 ريال
− الخصومات الواقعة حتى اليوم (غياب، تأخير، مخالفات، أقساط سلف، مشتريات)
= الصافي التقديري الآن
```

وتعرض كذلك الأيام المنقضية والمتبقية، وراتب الشهر كاملاً إن أكمله بلا خصومات. عدد أيام
الشهر المعتمد (٣٠ افتراضياً) من **الإعدادات ← قواعد الرواتب**. والإدارة ترى الكشف نفسه
لكل الموظفين عبر `GET /api/payroll/to-date`.

## مشتريات الموظفين

**مشتريات الموظفين ← تسجيل فاتورة**: الموظف اشترى من المتجر بـ ١٠ ريال، فتُسجَّل عليه
فاتورة بتاريخها وبيانها ورقمها، وتُخصم تلقائياً في مسير **الشهر الذي يقع فيه تاريخها**،
وتظهر في قسيمته وفي جدول الرواتب بعمود «مشتريات».

- يصل الموظف إشعار بكل فاتورة، ويرى فواتيره في الشاشة نفسها (ولا يرى فواتير غيره).
- الفاتورة **لا تُحذف**: تُلغى بسبب مكتوب فتبقى في السجل ولا تُخصم.
- لا تُقبل فاتورة في شهر مسيره **معتمد** — ألغِ اعتماد المسير أولاً.

## شاشة الطلبات: كل ما يرفعه الموظف من مكان واحد

أيقونة **الطلبات** في شريط الموظف السفلي صارت مركز كل طلباته. أربعة أزرار في أعلى الشاشة:

| الطلب | ما يحويه |
|---|---|
| **إجازة** | النوع والتاريخان والسبب، مع إرفاق مستند |
| **بصمة فائتة** | الوقت الفعلي ونوع البصمة وسبب نسيانها |
| **سلفة** | المبلغ والقسط وشهر البداية — وبعد الاعتماد يقرّ باستلامها من الشاشة نفسها |
| **طلب آخر** | تعريف أو شهادة، تغيير وردية، تصحيح بيانات، شكوى، اقتراح، أو غيرها |

وتحتها **قائمة موحّدة** تجمع طلباته كلها بأنواعها مرتّبةً بالأحدث: نوع الطلب وتفاصيله
وحالته ورد الإدارة عليه، مع زر **إلغاء** للمعلّق و**إقرار بالاستلام** للسلفة المعتمدة.

والإدارة ترى الطلبات العامة في **الإجازات ← طلبات الموظفين**، فتعتمد أو ترفض بردّ مكتوب
يصل الموظف إشعاراً ويظهر في شاشته.

## طلب «نسيت البصمة»

من شاشة الموظف: **نسيت البصمة؟** ← يحدد الوقت الفعلي ونوع البصمة (حضور / انصراف /
استراحة) ويكتب السبب. الطلب يصل للموارد البشرية في شاشة **طلبات البصمة**، وعند اعتماده:

- تُسجَّل البصمة فعلياً بالوقت المطلوب، مصدرها «إدخال يدوي» وملاحظتها تحمل سبب الطلب.
- يُعاد احتساب اليوم تلقائياً، فتتحوّل حالته من «انصراف ناقص» إلى «حاضر».
- يصل الموظف إشعار بالنتيجة، والرفض يصله بسببه.

لا تُقبل طلبات أقدم من ٣٠ يوماً، ولا بوقت مستقبلي، ولا طلب مكرر بالوقت نفسه. وللموظف
سحب طلبه ما دام معلّقاً.

## المستحقات والخصومات المرحّلة

جدول مستقل في **شؤون الموظفين ← المستحقات المرحّلة** للحركات المالية القادمة من شهور سابقة.

**المشكلة التي يحلّها:** موظف لم يُصرف له راتب أربعة أيام من الشهر الماضي. تلك الأيام
**لا تُقيَّد إجازةً ولا غياباً** في الشهر الحالي — تُسجَّل حركة مالية مستقلة:
«مستحق راتب مرحّل من الشهر السابق - 4 أيام».

كل حركة تحمل:

| الحقل | المعنى |
|---|---|
| نوع الحركة | **مستحق سابق** (يُضاف) أو **خصم سابق** (يُخصم) |
| الشهر الذي تخصّه | لا شهر الصرف |
| عدد الأيام | ٤ مثلاً |
| قيمة اليوم | تُحتسب من راتب الموظف إن تُركت فارغة |
| إجمالي المبلغ | الأيام × قيمة اليوم (أو مبلغ مباشر) |
| السبب وملاحظة الإدارة | نصّ حر |
| حالة الصرف | **غير مصروف** أو **مصروف** |

**الدورة:** كل حركة «غير مصروفة» تدخل تلقائياً في أقرب مسير — المستحق يُضاف والخصم يُخصم،
وتظهر في القسيمة والجدول وملف الإكسل بعمودَي «مستحق مرحّل» و«خصم مرحّل». وعند **اعتماد**
المسير تُعلَّم **مصروف** برقم المسير وتاريخه، و**إلغاء الاعتماد** يعيدها «غير مصروف».
والحركة غير المصروفة تُعدَّل أو تُلغى بسبب مكتوب؛ المصروفة لا تُمس.

## فحص ما قبل إقفال الشهر

زر **«فحص ما قبل الإقفال»** في صفحة الرواتب يفحص الشهر ويعرض لك، لكل موظف، ما يحتاج معالجة
قبل احتساب المسير واعتماده:

1. **أيام غياب** بلا بصمة وبلا إجازة.
2. **تجاوز رصيد الإجازة** (المستخدم أكثر من المستحق + المرحّل).
3. **مستحقات مرحّلة** من شهر سابق لم تُصرف.
4. **خصم مسجَّل لم يُعتمد** (مخالفة بانتظار الإقرار أو التظلّم أو الاعتماد).
5. **بصمة دخول بلا خروج** أو استراحة بلا عودة.

النتيجة تُعرض مصنّفة بعدّاد لكل حالة وتفصيلها بالتواريخ والمبالغ، وزر
**«إرسال الملخّص للإدارة»** يرسلها إشعاراً لمديري النظام والموارد البشرية.

## تصدير جدول الرواتب: Excel وطباعة و CSV

ثلاثة أزرار بجانب كل مسير في صفحة **الرواتب**:

| الزر | المخرج |
|---|---|
| **القسائم PDF** | قسيمة مستقلة لكل موظف، جاهزة للطباعة أو الحفظ PDF |
| **طباعة الجدول** | جدول كامل في صفحة A4 أفقية بمجاميع وخانات توقيع والمبلغ كتابةً |
| **Excel** | ملف `.xlsx` منسّق |
| **CSV** | ملف نصّي بسيط لمن يريد معالجته آلياً |

**ملف Excel** ليس تصديراً خاماً:

- ورقة **عربية من اليمين لليسار** باسم الشهر.
- ترويسة باسم المنشأة والشهر وحالة المسير وعدد الموظفين وتاريخ التصدير.
- ٢٤ عموداً: الأساسي والبدلات والإجمالي، أيام الحضور والغياب والإجازات، التأخير والإضافي،
  وكل الخصومات (غياب، تأخير، إجازة بلا راتب، مخالفات، سلف، مشتريات، استراحة بلا عودة)،
  ثم الصافي.
- **سطر مجاميع بمعادلات `SUM` حيّة** — لو عدّلت رقماً داخل إكسل تتحدّث المجاميع تلقائياً.
- **تثبيت الرؤوس** و**فلاتر** على الأعمدة، وتنسيق أرقام `#,##0.00`.
- **إعداد طباعة أفقي** يضغط الجدول في عرض الصفحة، مع تكرار سطر العناوين في كل صفحة.
- خانات توقيع: أعدّه / راجعه / اعتمده.

## إلغاء اعتماد مسير الرواتب

المسير المعتمد يُقفل عن التعديل. ولإعادة فتحه: **الرواتب ← إلغاء الاعتماد** مع **سبب إلزامي**.

- يعود المسير **مسودة** قابلة للتعديل وإعادة الاحتساب.
- تختفي القسائم من شاشات الموظفين (لا تُعرض إلا قسائم المسير المعتمد)، ويصلهم إشعار بأنها
  قيد المراجعة.
- السبب واسم من ألغى ووقت الإلغاء تُحفظ في **سجل التدقيق**.
- وحذف مسير معتمد ممكن كذلك، لكن بسبب مكتوب يُحفظ في سجل التدقيق أيضاً.

## تسجيل حضور جماعي لفترة

حين يعمل الفريق فعلاً ولا توجد بصمات (الجهاز لم يكن موصولاً بعد، أو انقطع الاتصال):
**الحضور اليومي ← تسجيل حضور جماعي**، حدّد «من تاريخ» و«إلى تاريخ» ثم نفّذ.

النظام ينشئ لكل موظف بصمة حضور وانصراف **بمواعيد ورديته** في أيام العمل ضمن المدى،
ثم يعيد احتساب الكشف — فتظهر الأيام **حاضر** بلا تأخير ولا خصم.

ما **لا** يمسّه أبداً (يُتخطّى ويُعرض عدده في نتيجة العملية):

| الحالة | السبب |
|---|---|
| يوم فيه بصمات فعلية | البيانات الحقيقية أدق ولا تُستبدل |
| الراحة الأسبوعية والراحة المجدولة | تسجيلها حضوراً يلغي حق الموظف في راحته |
| العطل الرسمية | تبقى عطلة في الكشف والراتب |
| الإجازات المعتمدة | لها رصيدها ومعالجتها الخاصة |
| ما قبل تاريخ التعيين، وأيام لم تأتِ بعد | لا معنى لحضور فيها |

لذلك **إعادة التشغيل على المدى نفسه لا تضاعف شيئاً**: الأيام التي سُجّلت تُعدّ «فيها بصمات»
فتُتخطّى. البصمات المُنشأة مصدرها «إدخال يدوي» وملاحظتها «تسجيل حضور جماعي»، فتبقى مميّزة
عن بصمات الجهاز في سجل البصمات، والعملية كلها مسجّلة في سجل التدقيق باسم منفّذها.
المدى الأقصى للعملية الواحدة ثلاثة أشهر، وهي متاحة للموارد البشرية ومدير النظام فقط.

## لوحة التعليمات الجانبية

في أعلى كل شاشة زر **(؟)** يفتح لوحة جانبية تشرح هذه الشاشة تحديداً: ماذا تفعل فيها،
والقواعد التي يطبّقها النظام خلفك، والحقول التي تؤثر على الحساب. تُغلق بزر الإغلاق أو
بالضغط خارجها أو بمفتاح Esc، وتعمل بالعربية والإنجليزية وعلى الجوال بعرض كامل.

## المخالفات والجزاءات

نموذج مبني على جدول المخالفات والجزاءات في لائحة تنظيم العمل:

1. **الإعدادات ← المخالفات والجزاءات**: عشرة أنواع جاهزة (عدم الالتزام بالزي، النظافة، **عدم التواجد
   في المكان المخصص**، مغادرة الموقع، معدات السلامة، التدخين، الجوال، سوء التعامل، رفض التعليمات،
   إتلاف الممتلكات) — كلها قابلة للتعديل، ويجب مطابقتها للائحة المعتمدة لدى منشأتك.
2. لكل نوع **سلّم جزاءات من أربع درجات** حسب التكرار: المخالفة الأولى، الثانية، الثالثة، الرابعة فأكثر.
   الجزاء إما إنذار، أو خصم نسبة من أجر يوم، أو خصم أيام، أو إيقاف بدون أجر، أو الفصل.
3. عند التسجيل يحسب النظام **رقم التكرار تلقائياً** خلال المدة النظامية (افتراضياً 180 يوماً، بعدها
   تُمحى المخالفة من سجل التكرار)، ويعرض الجزاء وقيمة الخصم بالريال قبل الحفظ.
4. المدير أو الموارد البشرية يسجّل المخالفة (مع إمكانية إرفاق مستند وتوثيق الموقع الجغرافي للرصد)،
   فيصل **إشعار فوري للموظف**، وله أن **يقرّ بالاطلاع** أو **يقدّم تظلّماً** يصل للموارد البشرية.
5. عند **اعتماد** المخالفة يُخصم مبلغ الجزاء تلقائياً في مسير رواتب الشهر الذي وقعت فيه.

## مسير الرواتب

يُحتسب من بيانات الحضور الفعلية: خصم الغياب (أجر يوم لكل يوم غياب)، خصم التأخير (بمقدار زمن التأخير،
وقابل للتعطيل)، **خصم الخروج المبكر**، خصم الإجازات بدون راتب، خصم المخالفات المعتمدة، وبدل العمل
الإضافي (أجر الساعة × 1.5 افتراضياً وفق نظام العمل). القواعد كلها قابلة للضبط من
**الإعدادات ← قواعد الرواتب**.

الأيام التي **لم تحن بعد** في الشهر الجاري لا تُحتسب غياباً ولا تُخصم.

### الخروج قبل نهاية الدوام

من انصرف قبل نهاية وردايته يُخصم عنه **بمقدار زمن خروجه المبكر** بأجر الساعة. ودقائق السماح
(**الإعدادات ← سياسة الحضور ← سياسة الخروج المبكر: دقائق السماح**، وافتراضها **5 دقائق**) عتبة
لا مطروحاً: من خرج قبل النهاية بأقل منها لا يُحتسب عليه شيء، ومن تجاوزها يُخصم عن **كامل** زمنه.

| وقت الانصراف (وردية تنتهي 17:00) | خروج مبكر | الخصم |
| --- | --- | --- |
| 16:57 | — | لا شيء (داخل السماح) |
| 16:54 | 6 دقائق | أجر 6 دقائق |
| 16:30 | 30 دقيقة | أجر 30 دقيقة |

لإيقاف الخصم والاكتفاء برصده في التقارير: **الإعدادات ← قواعد الرواتب ← خصم الخروج المبكر ← بدون خصم**.

> البصمة لا تُفهم انصرافاً إلا داخل **وقت السماح بالانصراف** (افتراضياً آخر 30 دقيقة من الوردية).
> فمن خرج قبل النهاية بأكثر من ذلك تُفهم بصمته **بدء استراحة**، ويُعامَل يومه معاملة الاستراحة
> بلا عودة (نصف يوم) لا الخروج المبكر. فإن كان الخروج المبكر شائعاً لديكم بفارق أكبر، ارفعوا
> **وقت السماح بالانصراف** بما يناسبه.

### الغياب بدون إذن مقابل الغياب بإذن

| الحالة | كيف تُسجَّل | الخصم |
| --- | --- | --- |
| غياب **بدون إذن** | يوم عمل بلا بصمة ولا إجازة | **أجر يومين** عن اليوم الواحد (المعامل الافتراضي 2) |
| غياب **بإذن** بدون راتب | إجازة من نوع «إجازة بدون راتب» معتمدة | أجر يوم واحد |
| غياب **بإذن** مدفوع | إجازة سنوية/اضطرارية/مرضية معتمدة | لا خصم |

معامل خصم الغياب يُضبط من **الإعدادات ← قواعد الرواتب ← خصم يوم الغياب بدون إذن (بالأيام)**،
ويقبل من 0 إلى 3. الأجر المخصوم يُحتسب من الراتب الكامل أو الأساسي حسب «أساس احتساب الخصم» أعلاه.

> تنبيه نظامي: الخصم الزائد عن أجر أيام الغياب يُعدّ جزاءً تأديبياً، فيجب أن يكون منصوصاً عليه في
> لائحة تنظيم العمل المعتمدة للمنشأة وفي حدود ما تجيزه المادة (المخالفات والجزاءات) من نظام العمل.

### الراتب الأساسي والبدلات

لكل موظف حقلان: **الراتب الأساسي** و**البدلات** (سكن، مواصلات… كمبلغ شهري واحد)، وإجمالي الراتب =
الأساسي + البدلات. القسيمة تعرض العمودين وتضيفهما معاً إلى الصافي.

**أساس احتساب الخصم وأجر اليوم** يُضبط من **الإعدادات ← قواعد الرواتب**:

| الخيار | أجر اليوم | متى تختاره |
| --- | --- | --- |
| الأساسي + البدلات (افتراضي) | الإجمالي ÷ أيام الشهر | حين يكون الأجر المتفق عليه هو الإجمالي |
| الأساسي فقط | الأساسي ÷ أيام الشهر | حين تكون البدلات غير خاضعة للخصم |

ونفس الأساس يُستخدم في احتساب جزاءات المخالفات (خصم يوم أو نسبة من أجر يوم).

### استيراد كشف الرواتب والفترات

قالب الاستيراد يحتوي عمودَي **الوردية** و**البدلات**، فيمكن رفع كشف الموظفين كاملاً دفعة واحدة موزعاً
على الفترات. يوجد ملف جاهز كمثال: `deploy/samples/roster_mara_lounge.csv` (فترة صباحية وفترة مسائية،
مع المسمى الوظيفي والأساسي والبدل لكل موظف).

- عمود **الإدارة** يُستخدم للفترة (الفترة الصباحية / الفترة المسائية) ليظهر التجميع في التقارير.
- عمود **الوردية** يجب أن يطابق اسم وردية معرّفة مسبقاً (`الوردية الصباحية`، `الوردية المسائية`)
  وإلا استُورد الموظف بدون وردية مع تنبيه في تقرير الاستيراد.
- بعد الرفع: عدّل أوقات كل وردية وأيام عملها من **الموظفون ← الورديات**، وغيّر أرقام الموظفين
  لتطابق أرقامهم في جهاز البصمة.

## تسجيل دخول الموظفين

**رقم الجوال هو التصريح بالدخول:** بمجرد تسجيل رقم جوال لموظف (يدوياً أو عبر الاستيراد)
يُنشأ له حساب تلقائياً — اسم المستخدم وكلمة المرور المؤقتة هما الرقم نفسه — ويُطالَب بتغيير
كلمة المرور فور أول دخول قبل أن يتمكن من استخدام النظام.

- حقل الدخول يقبل **اسم المستخدم أو رقم الجوال** بأي صيغة: `0501234567`، `+966501234567`،
  `966501234567`، أو بمسافات — يُوحَّد الرقم قبل المطابقة.
- **لا يُقبل تكرار رقم الجوال بين موظفَين** لأنه وسيلة دخول: يُرفض الحفظ برسالة تسمّي صاحب الرقم،
  وفي الاستيراد يُستورد الموظف بدون رقم مع تنبيه في التقرير.
- الحساب الموقوف لا يدخل بأي منهما، وكلمة المرور مطلوبة دائماً.
- الخاصية تُوقَف من **الإعدادات ← التنبيهات وإشعارات الجوال ← حسابات دخول الموظفين**، وفيها
  زر **«إنشاء حسابات لكل من له رقم جوال»** للأرقام المسجّلة قبل تفعيل الخاصية.
- **حساب كل موظف يُدار من ملفه** (الموظفون ← تعديل ← حساب دخول الموظف): تظهر حالة الحساب
  (اسم المستخدم، مفعّل أو موقوف، كلمة مرور مؤقتة، تحقق بخطوتين، آخر دخول ناجح) مع ثلاثة أزرار:
  **إنشاء حساب** لمن لا حساب له (ويوضّح سبب التعذّر إن لم يكن ممكناً)، **إعادة تعيين كلمة المرور**
  إلى رقم الجوال مع إنهاء جلساته المفتوحة فوراً، و**إيقاف الدخول / تفعيله**. كل إجراء يُسجَّل في
  سجل التدقيق باسم من نفّذه.

> ملاحظة أمنية: كلمة المرور المؤقتة معروفة (رقم الجوال)، ولذلك يُلزم النظام الموظف بتغييرها في
> أول دخول. من يدخل أولاً يملك الحساب، فالأفضل إبلاغ الموظف بمجرد تسجيل رقمه.

## السلف على الراتب: اعتماد ثم إقرار استلام

**دورة السلفة أربع خطوات، ولا يُخصم قسط قبل أن يقرّ الموظف باستلام المبلغ:**

1. **الطلب**: الموارد البشرية تسجّلها، أو **الموظف يطلبها بنفسه** من شاشة «السلف ← طلب سلفة».
   الحالة: *بانتظار الاعتماد*.
2. **الاعتماد**: الموارد البشرية تعتمد أو ترفض بملاحظة. الحالة بعد الاعتماد:
   *بانتظار إقرار الاستلام*، ويصل الموظف إشعار.
3. **إقرار الاستلام**: الموظف يضغط **«أقرّ باستلام السلفة»**، فتصبح *سارية*، ويصل الإدارة إشعار.
4. **الخصم**: تبدأ الأقساط تُخصم من مسير الرواتب حسب الجدول.

> **لماذا هذا الترتيب:** لئلا يُخصم من راتب أحد مبلغ لم يستلمه. المرفوضة تُلغى ولا يُخصم منها شيء.

وبقية التفاصيل:

- الأقساط محسوبة حسابياً من (المبلغ ÷ القسط)، وآخر قسط يأخذ الباقي — مثال: ١٢٠٠ ريال بقسط ٣٠٠ = ٤ أقساط.
- القسط يُخصم تلقائياً في مسير الرواتب في شهره فقط، **وإعادة احتساب المسير لا تُكرّر الخصم**.
- الصفحة تعرض لكل سلفة: المسدَّد، المتبقي، عدد الأقساط، وشريط تقدّم.
- «إلغاء» يوقف الخصم من الشهر التالي، و«تسديد كامل» يقفل السلفة، والحذف ممنوع إذا خُصم قسط
  منها في مسير معتمد.
- الموظف يرى سلفه فقط، وتظهر في قسيمة راتبه بعمود «قسط السلفة».

## قسيمة الراتب (طباعة / PDF)

لكل قسيمة زر **«قسيمة»** يفتح مستنداً أنيقاً بحجم A4 جاهزاً للطباعة أو الحفظ بصيغة PDF
(من نافذة الطباعة ← «حفظ بصيغة PDF»)، ويحوي:

- شعار المنشأة واسمها وفترة الراتب ورقم القسيمة وحالتها.
- بيانات الموظف: الاسم والرقم والمسمى والإدارة وتاريخ التعيين والوردية.
- ملخص الحضور: أيام الحضور والغياب والإجازات ودقائق التأخير والإضافي.
- جدولَي **المستحقات** و**الاستقطاعات** (شاملاً قسط السلفة) بإجماليهما.
- صافي الراتب رقماً و**تفقيطاً بالعربية** («فقط سبعة آلاف وثمانمئة وخمسة عشر ريالاً لا غير»).
- خانات توقيع الموظف والموارد البشرية والإدارة المالية.

ومن صفحة الرواتب زر **«القسائم PDF»** يطبع قسائم المسير كلها، كل موظف في صفحة مستقلة.
الموظف يطبع قسيمته المعتمدة فقط من **الرواتب ← قسيمتي**، ويصله إشعار على جواله فور اعتماد المسير.

> التحويل إلى PDF يتم في المتصفح نفسه، فلا حاجة إلى خطوط أو حزم إضافية على الخادم،
> وتظهر العربية بخطها الصحيح على الكمبيوتر والجوال.

## تنبيه الغياب والتأخير

مهمة يومية تفحص الحضور بعد بداية وردية كل موظف بمدة قابلة للضبط (٦٠ دقيقة افتراضياً)، وترسل
تنبيهاً واحداً يومياً إلى الموارد البشرية ومدير الإدارة يحوي: **من لم يبصم** و**من تأخر وكم دقيقة**،
وتُنبّه الموظف نفسه أيضاً (قابل للإيقاف). الضبط من **الإعدادات ← التنبيهات وإشعارات الجوال**،
وفيها زر «إرسال التنبيه الآن» للفحص الفوري.

## إشعارات الجوال (Web Push)

يصل الإشعار بنغمة الجهاز حتى والتطبيق مغلق، بلا حساب خارجي ولا خدمة مدفوعة:

1. مفاتيح VAPID تُولَّد تلقائياً عند أول تشغيل وتُحفظ في إعدادات النظام.
2. كل مستخدم يفعّلها على جهازه من **حسابي ← إشعارات الجوال** (زر تفعيل + زر إشعار تجريبي).
3. كل إشعار داخل النظام (إجازة، مخالفة، وثيقة، سلفة، غياب) يُرسَل تلقائياً إلى أجهزة المستخدم.
4. الاشتراكات المنتهية تُحذف تلقائياً عند أول محاولة إرسال فاشلة.

**متطلبات:** HTTPS (متوفر عبر Let's Encrypt في سكربت التثبيت)، وعلى الآيفون يجب إضافة النظام
إلى الشاشة الرئيسية أولاً (iOS 16.4 فأحدث). التفعيل العام من **الإعدادات ← التنبيهات وإشعارات الجوال**.

## ربط جوجل شيت (بدون تعقيد)

يستطيع النظام إنزال بياناته في ملف Google Sheets تلقائياً: **البصمات** فور تسجيلها، **ملخص
الحضور اليومي**، **الإجازات**، **المخالفات المعتمدة**، و**قسائم الرواتب** بعد الاعتماد — كل نوع
في ورقة مستقلة بعناوين عربية.

**الإعداد مرة واحدة (٥ خطوات، بلا حساب Google Cloud ولا مفاتيح JSON):**

1. أنشئ ملف Google Sheets جديداً.
2. **الإضافات (Extensions) ← Apps Script**.
3. احذف الكود الموجود والصق محتوى [`deploy/google_apps_script.gs`](deploy/google_apps_script.gs).
4. غيّر `SECRET` في أول السكربت إلى كلمة سر، ثم **Deploy ← New deployment ← Web app** مع
   `Execute as: Me` و`Who has access: Anyone`.
5. في النظام: **الإعدادات ← ربط جوجل شيت** — الصق الرابط (ينتهي بـ `/exec`) وكلمة السر نفسها،
   واختر البيانات المطلوبة، ثم **اختبار الاتصال**.

**لماذا هذه الطريقة؟** لا تحتاج مشروعاً في Google Cloud ولا حساب خدمة ولا صلاحيات OAuth؛ السكربت
يعمل داخل ملفك بصلاحيتك أنت، ويرفض أي طلب لا يحمل كلمة السر.

**الموثوقية:** كل دفعة تُحفظ في صندوق إرسال داخل قاعدة البيانات قبل إرسالها، فإن انقطعت الشبكة
أو تعطّل جوجل تُعاد المحاولة تلقائياً (حتى ١٢ محاولة) ولا يضيع أي صف. تظهر الحالة في نفس الشاشة:
المعلّق، المُرسل اليوم، الفاشل، وآخر خطأ. وزر **إعادة مزامنة فترة كاملة** يعيد بناء أي ورقة من الصفر.

## قواعد الاحتساب

- **الحضور** = أول بصمة في نافذة اليوم، **الانصراف** = آخر بصمة (الورديات الليلية تمتد لليوم التالي).
- **تأخير** = فارق الدخول عن بداية الوردية إذا تجاوز دقائق السماح (يُحتسب من بداية الوردية).
- **خروج مبكر** = فارق الانصراف قبل نهاية الوردية إذا تجاوز دقائق السماح.
- **وقت إضافي** = ما بعد نهاية الوردية إذا تجاوز السماح، والعمل في يوم راحة يُحتسب كاملاً إضافياً.
- **حالات اليوم**: حاضر / متأخر / انصراف ناقص (بصمة واحدة) / إجازة معتمدة / عطلة رسمية /
  راحة أسبوعية / غياب.
- إعادة الاحتساب تلقائية عند: استيراد بصمات، إدخال يدوي، اعتماد أو إلغاء إجازة، تعديل العطل.

### تجميد أيام الماضي: تعديل الوردية لا يعيد كتابة ما مضى

**كل يوم حضور يُختم بلقطة الوردية التي حُسب بها** — اسمها وأوقاتها ودقائق سماحها وأيام عملها.
وإعادة الاحتساب بعدها تستعمل تلك اللقطة لا وردية الموظف اليوم. فالماضي يبقى كما وقع.

هذا يمنع خللاً كان قائماً: نقل الموظف إلى وردية أخرى، أو تعديل أوقات ورديته، كان يُعيد حساب
الشهر الماضي بالوردية الجديدة — فيتحوّل يوم كان **حاضراً** إلى **انصراف مفقود** أو
**تحتاج مراجعة** (= خصم نصف يوم)، بلا أن تتغيّر بصمة واحدة. ولم يكن يحتاج زراً: **بناء مسير
الرواتب نفسه يستدعي إعادة الاحتساب** للشهر كله، فتتبدّل الأيام تحت المسير بلا إشعار.

- **اليوم الجاري وما بعده** يتبعان الوردية الحالية دائماً، فتعديل الوردية يسري من اليوم فصاعداً.
- **جدول الحضور يُظهر الوردية المستعملة** لكل يوم تحت اسم الموظف: «الوردية الصباحية (06:00–18:00)»،
  فيُعرف سبب احتساب اليوم كما احتُسب.
- **الاستثناء الصريح**: الحضور اليومي ← **إعادة الاحتساب** ← «الوردية الحالية للموظف» يعيد حساب
  الماضي بالوردية المسندة الآن — لتصحيح إسناد وردية خاطئ. يطلب تأكيداً ويُسجَّل في سجل التدقيق.
- عند الترقية تُختم كل الأيام المحفوظة سابقاً بوردية الموظف الحالية مرة واحدة (لا يمكن استرجاع
  ورديات لم تُسجَّل)، ومن تلك اللحظة يصير الماضي محفوظاً.
- ملاحظة: اللقطة تحفظ **الوردية وأيام الراحة الأسبوعية**. أما سياسات الحضور العامة
  (دقائق السماح، مدة الاستراحة المسموحة) فما زال تعديلها يسري على الماضي عند إعادة الاحتساب.

### قفل الشهر المعتمد

**اعتماد مسير الرواتب يقفل حضور ذلك الشهر.** الاعتماد يعني أن الرواتب صُرفت على هذه
الأرقام، فأي تغيير في حضوره بعده يجعل القسيمة المصروفة لا تطابق بياناتها.

ما يُرفض داخل شهر مُقفل (برسالة تسمّي الشهر وطريق الفتح):

| العملية | السلوك |
|---|---|
| بصمة يدوية جديدة | مرفوضة |
| تعديل بصمة أو نقلها أو حذفها | مرفوض |
| التعديل اليدوي على يوم حضور | مرفوض |
| تسجيل حضور جماعي | مرفوض |
| تحديد يوم راحة أو إلغاؤه | مرفوض |
| إعادة الاحتساب (يدوية أو تلقائية) | **تتخطّى** الشهر وتقول ذلك، ولا تكتب فوقه |

- **بصمات الجهاز والتطبيق تُسجَّل دائماً** ولا تُرفض — لا يضيع سجل خام أبداً. لكنها لا تغيّر
  يوماً في شهر مُقفل حتى يُفتح.
- إعادة الاحتساب تعمل على بقية الفترة طبيعياً، وتتخطّى المقفل وحده: «تمت إعادة احتساب ١٢ يوماً
  — وتُخطّي ٨/٢٠٢٦ لأن مسير رواتبه معتمد».
- **المفتاح**: الرواتب ← المسير ← **إلغاء الاعتماد** (بسبب مكتوب يُحفظ في التدقيق) يفتح الشهر،
  فيُصحَّح، ثم يُعاد الاعتماد. فالقفل يمنع التغيير الصامت لا التصحيح المقصود.
- تظهر لافتة **«الشهر مُقفل»** في شاشة الحضور اليومي عند اختيار يوم داخله، وفي تفاصيل المسير
  المعتمد، وفي نافذة إعادة الاحتساب قبل التنفيذ.

## العمل الإضافي: لا يُحتسب إلا باعتماد الإدارة

**القاعدة:** ما يعمله الموظف بعد نهاية دوامه يُسجَّل **وقتاً زائداً** ولا يدخل الراتب. فإن
اعتمدته الإدارة صار **عملاً إضافياً معتمداً** يُحتسب مالياً. وإن رُفض لم يُحتسب.

| الحالة | المعنى | في الراتب |
|---|---|---|
| بانتظار الموافقة | رصده النظام ولم يُبتّ فيه | لا يدخل |
| معتمد | وافقت الإدارة | يُحتسب بمعامل الإضافي |
| مرفوض | لم توافق الإدارة | لا يُحتسب |

- **كل قرار باسم صاحبه**: يُحفظ اسم من اعتمد أو رفض، وتاريخ القرار ووقته بالدقيقة،
  وملاحظته — في السجل وفي سجل التدقيق. فلا يطالب موظف لاحقاً بساعات لم تُعتمد رسمياً.
- **اعتماد جزئي**: يمكن اعتماد بعض الوقت المرصود (٦٠ من ٩٠ دقيقة مثلاً)، ولا يُقبل
  اعتماد أكثر منه. والباقي يظهر «غير معتمد».
- **القرار لا تمحوه إعادة الاحتساب**: السجل المعتمد أو المرفوض يبقى شاهداً على قرار
  الإدارة مهما أُعيد حساب اليوم. لتصحيح قرار: **إعادة فتح** ثم البتّ من جديد، بأثر في التدقيق.
- **الشاشات**: «الحضور ← الوقت الإضافي» للإدارة (بانتظار/معتمد/مرفوض مع ملخص الشهر)،
  و«وقتي الإضافي» للموظف يرى فيها حالة كل يوم ومن بتّ فيه. ويصل الموظف إشعار بكل قرار.
- **في القسيمة**: عمودان منفصلان — «إضافي معتمد (د)» و«زائد غير معتمد (د)» — فلا يلتبس
  المصروف بغيره.
- تُوقَف القاعدة من **الإعدادات ← التنبيهات ← احتساب العمل الإضافي ← تلقائي بلا اعتماد**،
  فيعود احتساب كل وقت زائد كما كان.

## بيان الخصومات: لا يُخصم ريال بلا سبب ويوم

كل خصم في القسيمة يُحفظ **سطراً مستقلاً** بنوعه ويومه وسببه ومبلغه:

| اليوم | النوع | السبب | المبلغ |
|---|---|---|---|
| 2026-08-02 | غياب | غياب بدون إذن — أجر ٢ يوم | 533.33 |
| 2026-08-08 | تأخير | تأخير ٦٠ دقيقة عن بداية الدوام | 50.00 |
| 2026-08-08 | خروج مبكر | خروج قبل نهاية الدوام بـ ٢٠ دقيقة | 16.67 |

- الموظف يرى بيان خصوماته في قسيمته المعتمدة، ولا يرى قسائم غيره.
- المجموع المفصّل يطابق إجمالي الخصومات في القسيمة؛ وأي فرق يظهر سطراً باسم
  «(فرق تسوية)» بدل أن يُخفى.

## الواجهة والتصميم

واجهة عربية (RTL) بنظام تصميم موحّد داخل `frontend/styles.css` — بلا مكتبات خارجية ولا رسوم ثقيلة،
فحجم الواجهة كلها ملفّان (CSS + JS) وتعمل بسرعة على الجوال:

- **لوحة ألوان موحّدة** في متغيرات CSS (`:root`): أزرق `#2563EB` أساسي، تركواز `#14B8A6` ثانوي،
  خلفية `#F8FAFC`، بطاقات بيضاء، نص `#1E293B` وثانوي `#64748B`، حدود `#E2E8F0`،
  وحالات: نجاح `#22C55E`، تنبيه `#F59E0B`، خطأ `#EF4444`. تغيير أي لون = سطر واحد في `styles.css`.
- **أيقونات خطية موحّدة** (SVG داخل `frontend/icons.js`): سماكة وزوايا واحدة، ترث لون النص
  وتتكيّف مع الوضع الفاتح/الداكن — بلا إيموجي وبلا مكتبة أيقونات خارجية. لإضافة أيقونة:
  سطر واحد في `ICON_PATHS` ثم `icon('اسمها')`.
- **قائمة جانبية مجمّعة** (عام / الحضور / الإجازات / شؤون الموظفين / الإدارة) قابلة للتصغير إلى أيقونات،
  وتتحوّل إلى درج منزلق على الجوال.
- **لوحة مؤشرات**: بطاقات بأيقونات وألوان حالة، إجراءات سريعة، رسم أعمدة لآخر ٧ أيام،
  ورسم دائري (SVG) لتوزيع الموظفين على الإدارات. للموظف: مؤشرات شخصية فقط.
- **الموظفون**: عرض بطاقات أو جدول، بصورة رمزية بالأحرف الأولى، والحالة، ومدة الخدمة.
- **ملف الموظف**: تبويبات (نظرة عامة، الحضور، الإجازات، الراتب، المخالفات، الوثائق، الجدول الزمني)،
  مع أشرطة تقدّم لنسبة الحضور ورصيد الإجازة وفترة التجربة ومدة العقد المتبقية (من وثيقة العقد).
- **تقويم حضور شهري** ملوّن حسب الحالة، وبطاقات لطلبات الإجازة، وملخص لمسير الرواتب.
- **مركز التنبيهات**: فلاتر حسب النوع (وثائق / إجازات / مخالفات / رواتب) وتعليم الكل كمقروء.
- **تفاصيل**: هياكل تحميل (Skeleton)، تنبيهات Toast بأيقونات، حركات ظهور خفيفة تحترم
  `prefers-reduced-motion`، وتجاوب كامل على الجوال والتابلت.

### اللغة: عربي / English

زر 🌐 في الشريط العلوي (وفي شاشة الدخول) يبدّل لغة الواجهة. الإنجليزية تقلب الاتجاه إلى LTR
وتترجم القوائم والشاشات والحالات والرسائل، وتبقى البيانات (أسماء الموظفين والإدارات) كما أُدخلت.
القاموس في `frontend/i18n.js`: أضف أي عبارة جديدة كسطر واحد `'النص العربي': 'English text'` —
وما لا ترجمة له يظهر عربياً بدل أن يختفي.

### أيام الراحة الأسبوعية والشهرية

- **راحة أسبوعية لكل موظف** (الموظفون ← تعديل): تُحدَّد أيامه فيعمل بقية الأسبوع، فتختلف
  راحة كل موظف داخل الوردية نفسها. إن تُركت فارغة يتبع أيام عمل الوردية.
- **راحة شهرية مجدولة** (صفحة «أيام الراحة»): اختر الموظف والشهر ثم اضغط على اليوم في التقويم
  ليصبح يوم راحة (وضغطة ثانية تلغيه). ولا يقبل النظام تجاوز الرصيد.
- **رصيد الراحة الشهرية لكل موظف في ملفه** (الموظفون ← تعديل ← أيام الراحة الشهرية):
  «بلا راحة مجدولة» أو يوم أو يومان أو أربعة… ويغلب هذا الرقمَ العام. القيمة الافتراضية
  «افتراضي المنشأة» تعني اتباع الرقم في **الإعدادات ← التنبيهات ← الإجازات والراحة الشهرية**،
  فيكفي ضبطه مرة واحدة ثم استثناء من يختلف رصيده. الموظف ذو الرصيد الخاص يظهر بعلامة
  **«خاص»** في ملخص شاشة «أيام الراحة» وبشارة في بطاقته.
- يوم الراحة يظهر «راحة أسبوعية» بملاحظة «يوم راحة مجدول»، ولا يُحتسب غياباً ولا يُخصم،
  ويصل الموظف إشعار عند تحديده. العمل في يوم راحة يُحتسب كاملاً وقتاً إضافياً.

#### ما يراه الموظف من راحته

يرى الموظف **يوم راحته المعتمد** في تطبيقه، ولا يرى راحة زملائه:

- **شاشته الرئيسية**: صف «راحتك المعتمدة» بتاريخ أقرب يوم راحة قادم واسم يومه، يفتح جدوله.
- **المزيد ← جدولي ← أيام راحتي المعتمدة**: تواريخ الشهر كاملاً، كل يوم موسوم
  «قادمة» أو «اليوم» أو «مضت» مع ملاحظة الموارد البشرية إن كتبتها، وثلاثة أرقام:
  **المعتمد لك هذا الشهر**، و**مضى منها**، و**لم يُجدول بعد** من رصيده.
- **تقويم الشهر** في نفس الشاشة يمتد إلى نهاية الشهر (لا إلى اليوم)، فيظهر فيه يوم الراحة
  القادم بلون مميّز عن الراحة الأسبوعية العادية.
- التمييز مقصود: «راحة معتمدة» ليست «راحة أسبوعية»، فلا يخلط الموظف بين إجازته المعتادة
  وراحته الشهرية المستحقة.

الحماية من الـAPI نفسه: `GET /api/me/rest-days` يقرأ ملف صاحب الحساب وحده، ولا يقبل معرّف
موظف آخر أصلاً.

### أرصدة الإجازات معطّلة افتراضياً

المنشأة تعتمد على **طلبات الموظفين وقرار الإدارة** لا على رصيد محسوب مسبقاً. فافتراضياً:

- لا تظهر الأرصدة في **ملف الموظف** ولا في شاشة **«أرصدة الإجازات»** (وتُخفى من القائمة الجانبية)
  ولا في تطبيق الموظف ولا عند تقديم الطلب — تبقى **الطلبات** وحدها.
- **لا يُرفض طلب لنفاد الرصيد.** رسالة «الرصيد غير كافٍ» لا تظهر، والاعتماد قرار إداري.
- ما زال يعمل: نوع الإجازة، ومدفوعة أم بلا راتب، والحد الأقصى للأيام المتصلة، ومنع تعارض
  الطلبات، وخصم الإجازة بلا راتب في المسير.

**السجلات محفوظة ولا تُحذف**: أيام كل إجازة معتمدة تبقى مقيَّدة في الأرصدة خلف الستار، فبمجرد
إعادة التفعيل تظهر الأرقام صحيحة كما لو لم تتوقف. التبديل من
**الإعدادات ← التنبيهات ← الإجازات والراحة الشهرية ← نظام أرصدة الإجازات**.

وعند تفعيلها يعود إعداد **إظهار رصيد الإجازات للموظف** إلى العمل: افتراضياً **لا يرى الموظف
الأيام المتبقية** — يرى طلباته وحالتها فقط — والأرصدة كاملة أمام الموارد البشرية.

### تفصيل الراحة الأسبوعية

لكل موظف أيام راحة خاصة به (الموظفون ← تعديل ← أيام الراحة الأسبوعية): تُحدَّد أيامه بحيث
يعمل بقية الأسبوع، فتختلف راحة كل موظف داخل الوردية نفسها. إن تُركت فارغة يتبع أيام عمل الوردية.
يوم الراحة يظهر «راحة أسبوعية» ولا يُحتسب غياباً ولا يُخصم.

### بياناتي (تحديث ذاتي)

أيقونة **بياناتي** تتيح للموظف تحديث **رقم الهوية/الإقامة، الجوال، البريد** بنفسه؛ تُسجَّل التغييرات
في سجل التدقيق ويصل إشعار للموارد البشرية. بقية البيانات (الراتب، الوردية، تاريخ التعيين) للموارد
البشرية وحدها، وتظهر للموظف للاطلاع فقط.

### شاشة الموظف (بأسلوب تطبيقات البنوك)

الموظف يفتح التطبيق فيجد كل ما يلزمه في شاشة واحدة، بلا قوائم ولا أرقام تُرهقه:

- **بطاقة الحالة الكبيرة**: «أنت الآن: داخل الدوام / خارج الدوام / أنهيت دوام اليوم / اليوم راحتك»،
  وتحتها **زر واحد ذكي** يتغيّر حسب الحالة (تسجيل حضور ↔ تسجيل انصراف)، ومعه وقت الوردية
  واسم الفرع وحالة التحقق من الموقع.
- **بعد الضغط**: شاشة تأكيد قصيرة مع علامة صح متحركة واهتزاز: «تم تسجيل حضور — 8:57 ص — فرع مارا»،
  ثم تتحدّث البطاقة تلقائياً.
- **بقية الشاشة**: دوام اليوم (حضور/انصراف/تأخير)، آخر عملية حضور، الطلبات المعلّقة،
  تنبيه إن تأخر أو لم يبصم بعد بدء دوامه، وشريط جدول هذا الأسبوع. **بلا رصيد إجازات.**
- **شريط سفلي من خمسة أزرار فقط**: الرئيسية — الحضور — الطلبات — جدولي — حسابي.
- كل ذلك من **طلب واحد** (`GET /api/me/home`) فتفتح الشاشة فوراً على شبكة الجوال.

### على الجوال

- **شريط تنقل سفلي** بأهم خمس شاشات حسب الصلاحية، وفي وسطه زر **بصمة** بارز للموظف.
- **الجداول تتحوّل إلى بطاقات**: كل صف بطاقة، وكل قيمة بجانب اسم عمودها — بلا تمرير أفقي.
- **النوافذ تنفتح من الأسفل** (Bottom Sheet) بأزرار عريضة، وحقول بحجم 16px حتى لا يقرّب iOS الشاشة.
- الفلاتر حقلان في السطر، والشريط العلوي مختصر، مع احترام حواف الشاشة (`safe-area`) في آيفون.
- يعمل كتطبيق مثبَّت (PWA) مع إشعارات بنغمة الجهاز.
- **التحديثات تصل فوراً**: ملفات الواجهة تُجلب من الشبكة أولاً والذاكرة احتياط عند الانقطاع،
  ويُعاد تحميل التطبيق تلقائياً عند وصول نسخة جديدة. رقم الإصدار ظاهر في **حسابي** للتأكد.
- **آيفون تحديداً**: لافتة إرشاد لإضافة النظام إلى الشاشة الرئيسية (شرط الإشعارات في iOS)،
  ارتفاعات `dvh` تراعي شريط سفاري، إلغاء وميض اللمس، ومنع التقريب عند الكتابة.
- **مقاسات الآيفون كلها**: مُختبر على SE (375×667) وحتى Pro Max (430×932) — بلا تمرير أفقي.
- **أهداف لمس ≥44px** للأزرار والحقول وأيام التقويم وعناصر شريط التنقل.
- **الوضع الداكن**: يتبع إعداد الجهاز تلقائياً، وزر في الشريط العلوي يدور بين
  (تلقائي / فاتح / داكن) ويحفظ الاختيار لكل جهاز.
- **التقارير الطويلة** تُعرض بطاقات، ومعها زر **«عرض الجدول الكامل»** يفتح الجدول الحقيقي
  في ورقة منزلقة قابلة للتمرير أفقياً.
- **سرعة**: بلا أي إطار عمل (Vanilla JS)، والخط الخارجي يُحمَّل بلا حجب — جاهزية DOM ~٨٠ms
  وأول رسم ~٣٦٠ms، ومن الدخول إلى ظهور اللوحة كاملة أقل من نصف ثانية.

### أيقونة التطبيق على شاشة الجوال

الشعار الذي ترفعه في **الإعدادات ← هوية المنشأة** يصبح **أيقونة التطبيق خارج التطبيق**:
الأيقونة التي تظهر على شاشة الآيفون أو الأندرويد بعد «إضافة إلى الشاشة الرئيسية».

- النظام يبني تلقائياً المقاسات المطلوبة: `192` و`512` لأندرويد، `180` لـ apple-touch-icon،
  ونسخة `maskable` بهامش أمان للأقنعة الدائرية في أندرويد.
- الشعار يُقصّ من هوامشه الشفافة ثم يوضع في منتصف خلفية موحّدة — **أسود افتراضياً**
  لأنه الأنسب للشعارات الذهبية؛ ويمكن تغيير اللون من البطاقة نفسها.
- ملف `manifest.json` يُبنى ديناميكياً: اسم التطبيق على الشاشة = اسم المنشأة، وروابط
  الأيقونات تحمل بصمة إصدار (`?v=`) تتغيّر مع كل شعار جديد لكسر ذاكرة الأجهزة.
- إن لم يُرفع شعار (أو كان الملف SVG) يعود النظام إلى الأيقونة المدمجة في `frontend/assets`.
- **على الآيفون**: iOS يحتفظ بأيقونة الاختصار في ذاكرته، فبعد تغيير الشعار **احذف الاختصار
  من الشاشة الرئيسية وأضفه من جديد** حتى تظهر الأيقونة الجديدة.

ملاحظة: صور الموظفين تُعرض كأحرف أولى ملوّنة (لا يخزّن النظام صوراً)، و«الإنذارات» تُقرأ من
سجل المخالفات، و«العقد» من وثيقة نوعها «عقد» ذات تاريخ انتهاء.

## الحماية

### حماية الحساب والجلسة

- **التحقق بخطوتين (2FA)** بمعيار TOTP — يعمل مع Google Authenticator وMicrosoft
  Authenticator وغيرهما. التفعيل من **حسابي ← حماية الحساب**، والإيقاف يتطلب كلمة المرور.
  مبني على المكتبة القياسية بلا اعتماد خارجي (RFC 6238، هامش ±٣٠ ثانية لفرق ساعة الجهاز).
- **إبطال الجلسات**: كل توكن يحمل «نسخة جلسة». تغيير كلمة المرور — أو إعادة تعيينها من
  الإدارة، أو إيقاف الحساب، أو **«الخروج من كل الأجهزة»** — يزيد النسخة فيموت كل توكن
  صادر سابقاً في اللحظة نفسها. فالتوكن المسروق لا ينفع بعد تغيير كلمة المرور.
- **سجل الدخول**: كل محاولة تُسجَّل بوقتها وعنوانها وجهازها وسببها إن فشلت، ويطّلع عليها
  صاحب الحساب من **حسابي ← سجل الدخول**.
- **تنبيه الجهاز الجديد**: دخول ناجح من عنوان أو متصفح لم يُستخدم من قبل يُشعر صاحب
  الحساب فوراً، ويُشعر مديري النظام إن كان الحساب إدارياً.
- **تنبيه الهجوم**: خمس محاولات فاشلة على الحساب نفسه خلال ربع ساعة تُنبّه مديري النظام.
- **إيقاف بعد المحاولات**: ست محاولات فاشلة تُوقف المحاولة ربع ساعة (لكل حساب وعنوان).
- **خروج تلقائي** بعد ٣٠ دقيقة بلا استخدام على الجهاز نفسه.
- **كلمة المرور المؤقتة** من الإدارة تُلزم صاحبها بتغييرها عند أول دخول.

### حماية الخادم والمرفقات

- **حدّ معدل الطلبات**: ١٢٠٠ طلب/دقيقة لكل عنوان IP (يُضبط بـ `HR_RATE_LIMIT`) — يوقف
  الفحص الآلي والاستنزاف دون إزعاج فرع كامل يشترك في عنوان واحد.
- **فحص محتوى المرفقات**: لا يُكتفى بالامتداد — يُفحص التوقيع الفعلي للملف (magic bytes)،
  فملف تنفيذي باسم `logo.png` يُرفض، وملف SVG يحتوي `<script>` يُرفض.
- **المرفقات تُنزَّل ولا تُنفَّذ**: `Content-Disposition: attachment` مع
  `Content-Security-Policy: default-src 'none'; sandbox` على مسار `/uploads/`.


- **ترويسات أمنية** على كل استجابة: `Content-Security-Policy` (يمنع تحميل سكربتات خارجية
  وتضمين النظام داخل إطار)، `X-Frame-Options: DENY`، `X-Content-Type-Options: nosniff`،
  `Referrer-Policy`، `Permissions-Policy` (الموقع للنظام فقط، ولا كاميرا ولا ميكروفون)،
  و`Strict-Transport-Security` تلقائياً خلف HTTPS.
- **تحديد محاولات الدخول**: ٦ محاولات فاشلة خلال ١٥ دقيقة توقف المحاولات ١٥ دقيقة (لكل
  مستخدم/عنوان)، وتُسجَّل كل محاولة فاشلة في سجل التدقيق مع عنوان المصدر.
- **كلمات مرور**: رفض الشائعة (`123456`, `password`…) والمطابقة لاسم المستخدم أو رقم الجوال،
  وإلزام تغيير كلمة المرور المؤقتة عند أول دخول.
- **أجهزة البصمة**: لا يُقبل رقم تسلسلي جديد إلا أثناء **نافذة إقران** يفتحها المسؤول
  (أجهزة البصمة ← «فتح إقران جهاز جديد») أو قبل تسجيل أول جهاز. ما عدا ذلك تُرفض بـ403،
  فلا يستطيع أحد إرسال بصمات مزيّفة بانتحال جهاز.
- **CORS مغلق** افتراضياً (النظام والواجهة على نفس النطاق)، ويُفتح فقط بضبط `HR_CORS_ORIGINS`.
- **المرفقات** تُحفظ بأسماء عشوائية وتُقدَّم بترويسة `Content-Disposition: attachment` مع
  `sandbox`، فلا يُنفَّذ أي ملف مرفوع داخل المتصفح.
- **الصلاحيات** محصورة في الخادم لا في الواجهة: الموظف يرى نفسه فقط، والمدير فريقه،
  وكل إجراء حسّاس مسجّل في سجل التدقيق.

**يبقى عليك:** كلمة مرور قوية لـ `admin`، تحديث الخادم دورياً (`sudo apt update && sudo apt upgrade`)،
والاحتفاظ بنسخة احتياطية خارج الخادم (زر النسخ الاحتياطي أو رفع rclone اليومي).

## بنية المشروع

```
backend/app/
  main.py            نقطة التشغيل وتجميع المسارات والمزامنة التلقائية
  config.py          الإعدادات من متغيرات البيئة
  models.py          نماذج قاعدة البيانات
  schemas.py         مخططات الإدخال/الإخراج
  security.py        JWT، تجزئة كلمات المرور، والصلاحيات
  seed.py            تهيئة الجداول والحساب الأول والبيانات التجريبية
  migrate.py         إضافة الأعمدة الجديدة إلى قواعد بيانات قائمة
  routers/           auth, users, employees, attendance, leaves, devices, sites, violations,
                     payroll, hr_extra (إشعارات/تدقيق/وثائق/استيراد), reports, iclock
  services/          attendance (الاحتساب)، leave (الأرصدة والاعتماد)، zk_service (المزامنة)،
                     geo (التحقق الجغرافي)، violations (سلّم الجزاءات)، payroll (المسير)،
                     notifications (الإشعارات)، audit (سجل التدقيق)، settings_store (الإعدادات)
  zk/driver.py       طبقة بروتوكول ZKTeco (pyzk) + مولّد البيانات التجريبية
frontend/            واجهة عربية RTL (HTML/CSS/JS بدون أطر عمل) + manifest و service worker للتثبيت كتطبيق
backend/tests/       اختبارات شاملة للمسارات وقواعد الاحتساب
```

## متغيرات البيئة

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `HR_DATABASE_URL` | `sqlite:///data/hr.db` | رابط قاعدة البيانات — SQLite افتراضياً، ويدعم PostgreSQL (مُختبَر) عبر `postgresql+psycopg://...` |
| `HR_DATA_DIR` | `./data` | مجلد البيانات والمرفقات |
| `HR_SECRET_KEY` | يُولَّد تلقائياً | مفتاح توقيع التوكن |
| `HR_TOKEN_MINUTES` | `720` | مدة صلاحية الجلسة بالدقائق |
| `HR_TIMEZONE` | `Asia/Riyadh` | المنطقة الزمنية |
| `HR_AUTO_SYNC_MINUTES` | `0` | فترة المزامنة التلقائية للأجهزة (0 = معطّلة) |
| `HR_ADMIN_USERNAME` / `HR_ADMIN_PASSWORD` | `admin` / `admin123` | حساب مدير النظام الأول |
| `HR_SMTP_HOST` / `HR_SMTP_PORT` / `HR_SMTP_USER` / `HR_SMTP_PASSWORD` | فارغ | إشعارات البريد (اختياري) |
| `HR_WEBHOOK_URL` | فارغ | ويب هوك للإشعارات (واتساب/تلجرام عبر بوابة أو n8n) |

## النشر والاستضافة

راجع **[DEPLOY.md](DEPLOY.md)** — دليل كامل لخيارات الاستضافة (خادم سحابي، خادم داخل الشركة،
أو هجين) وأيها يناسب أجهزتك، مع ملفات جاهزة:

| الملف | الغرض |
|---|---|
| `deploy/install-ubuntu.sh` | تثبيت كامل بأمر واحد على Ubuntu (خدمة + Nginx + شهادة SSL) |
| `deploy/nginx.conf` | وسيط عكسي: HTTPS للموظفين وHTTP لمسار أجهزة البصمة `/iclock/` |
| `deploy/hr.service` | خدمة systemd تعمل تلقائياً عند الإقلاع |
| `Dockerfile` + `docker-compose.yml` | تشغيل بالحاويات |

أهم نقطتين: **HTTPS إلزامي** لعمل تحديد الموقع على الجوالات، و**موقع الخادم** يعتمد على وضع
أجهزة البصمة (السحب يتطلب خادماً داخل شبكة الأجهزة، والدفع يعمل مع أي خادم سحابي).
