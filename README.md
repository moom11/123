# نظام الموارد البشرية — الحضور والانصراف والإجازات (متكامل مع بصمة ZKTeco)

نظام كامل يعمل فعلياً: خادم **FastAPI + SQLite** وواجهة عربية (RTL) بدون أي أطر عمل خارجية،
مع تكامل حقيقي مع أجهزة البصمة **ZKTeco** بطريقتين: السحب المباشر عبر المنفذ `4370`،
والدفع اللحظي عبر بروتوكول **ADMS/iclock**.

## المزايا

- **الحضور والانصراف**: استيراد البصمات من الأجهزة، احتساب الحضور والتأخير والخروج المبكر
  والوقت الإضافي وساعات العمل، ودعم الورديات الليلية التي تعبر منتصف الليل.
- **الورديات**: أوقات دوام، دقائق سماح للدخول والخروج، استراحة، وأيام عمل لكل وردية.
- **الإجازات**: أنواع إجازات قابلة للتخصيص، أرصدة سنوية، احتساب الأيام مع استثناء العطل
  الأسبوعية والرسمية، دورة اعتماد (تقديم ← اعتماد/رفض ← إلغاء مع إرجاع الرصيد)، ومرفقات.
- **العطل الرسمية** وتأثيرها التلقائي على كشوف الحضور واحتساب الإجازات.
- **الصلاحيات**: مدير نظام / موارد بشرية / مدير إدارة (يرى ويعتمد فريقه) / موظف (يرى نفسه فقط).
- **التقارير**: لوحة مؤشرات، كشف يومي، كشف موظف لفترة، ملخص شهري، تقرير استثناءات،
  وتصدير CSV لكل ما سبق (يفتح مباشرة في Excel بترميز UTF-8).
- **إدارة الأجهزة**: اختبار الاتصال، مزامنة يدوية أو تلقائية، قراءة مستخدمي الجهاز واستيرادهم
  كموظفين، إرسال موظف إلى الجهاز، ضبط ساعة الجهاز، ومسح سجلاته بعد الاستيراد.
- **الحضور الذاتي من التطبيق مقيّداً بالموقع (Geofencing)**: الموظف يسجّل حضوره وانصرافه من
  جواله، ولا تُقبل البصمة إلا إذا كان داخل نطاق موقع عمل معتمد.
- **بصمة يدوية**: إدخال يدوي من الموارد البشرية عند نسيان الموظف البصم.

## التشغيل السريع

```bash
git clone <رابط المستودع> && cd 123
./run.sh --demo          # يثبّت المتطلبات، ينشئ القاعدة، ويعبّئ بيانات تجريبية
# أو بدون بيانات تجريبية:
./run.sh
```

ثم افتح: <http://localhost:8000>  — وتوثيق الـ API التفاعلي على `/docs`.

|---|---|---|
| `admin` | `admin123` | مدير النظام (يُنشأ دائماً عند أول تشغيل) |

## ربط جهاز البصمة ZKTeco

يدعم النظام الأجهزة التي تتكلم بروتوكول ZKTeco القياسي (iClock، K40، F18، MB360، uFace،
SpeedFace وغيرها). **شرط أساسي:** رقم الموظف في النظام = رقم المستخدم (PIN) في الجهاز.

### 1) وضع السحب (Pull) — الخادم يتصل بالجهاز

1. من الجهاز: `Comm ← Ethernet` واضبط عنوان IP ثابتاً (مثال `192.168.1.201`).
2. تأكد أن المنفذ `4370` مفتوح وأن الخادم في نفس الشبكة (أو يصل إليها عبر VPN).
3. في النظام: **أجهزة البصمة ← إضافة جهاز** ← الوضع «سحب» + IP + المنفذ + كلمة مرور الاتصال
   (Comm Key، افتراضياً `0`).
4. اضغط **اختبار** للتأكد من الاتصال، ثم **مزامنة** لسحب البصمات.
5. للمزامنة التلقائية: `HR_AUTO_SYNC_MINUTES=10` قبل تشغيل الخادم.

### 2) وضع الدفع (Push / ADMS) — الجهاز يرسل البصمة لحظياً

1. من الجهاز: `Comm ← Cloud Server / ADMS`.
2. `Server Address` = عنوان هذا الخادم، `Server Port` = منفذ التطبيق (`8000` افتراضياً).
3. احفظ وأعد تشغيل الجهاز؛ سيبدأ الاتصال بالمسار `/iclock/` وسيظهر تلقائياً في قائمة الأجهزة
   بعد أول اتصال (يمكنك بعدها إعادة تسميته وتحديد موقعه).

المسارات المنفَّذة من بروتوكول ADMS:
`GET /iclock/cdata` (المصافحة)، `POST /iclock/cdata?table=ATTLOG` (استقبال البصمات)،
`GET /iclock/getrequest` (سحب الأوامر المعلّقة)، `POST /iclock/devicecmd` (نتيجة الأمر)،
`GET /iclock/ping`.

> هذه المسارات لا تتطلب توكن لأن الأجهزة لا تدعمه؛ التمييز يتم بالرقم التسلسلي (SN).
> شغّل النظام داخل الشبكة الداخلية، ولا تعرّض مسار `/iclock/` للإنترنت مباشرة إلا خلف
> بوابة/جدار ناري يسمح بعناوين أجهزتك فقط.

### 3) الوضع التجريبي

جهاز بوضع «تجريبي» يولّد بصمات واقعية (تأخير/غياب/إضافي) لتجربة النظام كاملاً بدون عتاد.

## الحضور الذاتي من التطبيق مع التحقق من الموقع (Geofencing)

يستطيع الموظف تسجيل حضوره/انصرافه من التطبيق نفسه، **بشرط أن يكون داخل موقع العمل**:

1. **الإعدادات ← مواقع العمل والبصم الذاتي ← إضافة موقع**: أدخل اسم الموقع والنطاق المسموح
   بالأمتار (افتراضياً 150 م). اضغط **«📍 التقاط موقعي الحالي»** وأنت داخل المقر لتعبئة
   الإحداثيات تلقائياً، أو انسخها من خرائط Google (ضغط مطوّل على المكان).
2. اختيارياً: اربط كل موظف بموقع محدد من بطاقة الموظف (حقل «موقع العمل»). الموظف غير المرتبط
   بموقع يُقبل بصمه من أي موقع معتمد؛ والمرتبط بموقع لا يُقبل منه إلا من ذلك الموقع.
3. الموظف يفتح النظام على جواله ← **لوحة المؤشرات ← «تسجيل حضور / انصراف»**، فيطلب المتصفح
   إذن الموقع، ويتحقق الخادم من المسافة قبل قبول البصمة. زر **«التحقق من موقعي»** يعرض
   المسافة الحالية قبل التسجيل.

**ما الذي يرفضه النظام؟** البصم خارج النطاق (مع ذكر أقرب موقع والمسافة)، أو بدون إذن الموقع،
أو بدقة تحديد ضعيفة تتجاوز الحد المسموح (افتراضياً 150 م).

**ما الذي يُحفظ مع كل بصمة ذاتية؟** الإحداثيات، دقة التحديد، الموقع المطابق، والمسافة عنه —
وتظهر في «سجل البصمات» مع رابط لعرض النقطة على الخريطة.

**الإعدادات المتاحة** (الإعدادات ← مواقع العمل والبصم الذاتي):

| الإعداد | الوصف |
|---|---|
| السماح بالبصم من التطبيق | تعطيل/تفعيل الميزة كلياً |
| إلزام التواجد داخل موقع العمل | عند تعطيله يُقبل البصم من أي مكان (يبقى الموقع مسجلاً للمراجعة) |
| أقصى هامش خطأ للموقع | الحد الأعلى المقبول لدقة GPS بالأمتار |

> **متطلب تقني:** متصفحات الجوال لا تمنح صلاحية الموقع إلا عبر **HTTPS** (أو `localhost` أثناء
> التجربة)، لذا شغّل النظام خلف Nginx بشهادة SSL قبل اعتماد هذه الميزة على أجهزة الموظفين.

> **حدود الميزة بصراحة:** إحداثيات المتصفح يمكن تزييفها بتطبيقات Mock Location على أجهزة
> مُروَّتة. لذلك يبقى جهاز البصمة هو المصدر الأدق، ويُنصح باستخدام البصم الذاتي للمواقع
> الميدانية أو العمل خارج المقر، مع الاعتماد على تخزين الإحداثيات والمسافة لمراجعة أي حالة
> مشبوهة. الحد الأدنى لدقة التحديد يمنع أغلب الحالات العشوائية غير المتعمدة.

## قواعد الاحتساب

- **الحضور** = أول بصمة في نافذة اليوم، **الانصراف** = آخر بصمة (الورديات الليلية تمتد لليوم التالي).
- **تأخير** = فارق الدخول عن بداية الوردية إذا تجاوز دقائق السماح (يُحتسب من بداية الوردية).
- **خروج مبكر** = فارق الانصراف قبل نهاية الوردية إذا تجاوز دقائق السماح.
- **وقت إضافي** = ما بعد نهاية الوردية إذا تجاوز السماح، والعمل في يوم راحة يُحتسب كاملاً إضافياً.
- **حالات اليوم**: حاضر / متأخر / انصراف ناقص (بصمة واحدة) / إجازة معتمدة / عطلة رسمية /
  راحة أسبوعية / غياب.
- إعادة الاحتساب تلقائية عند: استيراد بصمات، إدخال يدوي، اعتماد أو إلغاء إجازة، تعديل العطل.

## بنية المشروع

```
backend/app/
  main.py            نقطة التشغيل وتجميع المسارات والمزامنة التلقائية
  config.py          الإعدادات من متغيرات البيئة
  models.py          نماذج قاعدة البيانات
  schemas.py         مخططات الإدخال/الإخراج
  security.py        JWT، تجزئة كلمات المرور، والصلاحيات
  seed.py            تهيئة الجداول والحساب الأول والبيانات التجريبية
  migrate.py         إضافة الأعمدة الجديدة إلى قواعد بيانات قائمة
  routers/           auth, users, employees, attendance, leaves, devices, sites, reports, iclock
  services/          attendance (الاحتساب)، leave (الأرصدة والاعتماد)، zk_service (المزامنة)،
                     geo (التحقق الجغرافي)، settings_store (إعدادات النظام)
  zk/driver.py       طبقة بروتوكول ZKTeco (pyzk) + مولّد البيانات التجريبية
frontend/            واجهة عربية RTL (HTML/CSS/JS بدون أطر عمل)
backend/tests/       اختبارات شاملة للمسارات وقواعد الاحتساب
```

## متغيرات البيئة

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `HR_DATABASE_URL` | `sqlite:///data/hr.db` | رابط قاعدة البيانات (يدعم PostgreSQL) |
| `HR_DATA_DIR` | `./data` | مجلد البيانات والمرفقات |
| `HR_SECRET_KEY` | يُولَّد تلقائياً | مفتاح توقيع التوكن |
| `HR_TOKEN_MINUTES` | `720` | مدة صلاحية الجلسة بالدقائق |
| `HR_TIMEZONE` | `Asia/Riyadh` | المنطقة الزمنية |
| `HR_AUTO_SYNC_MINUTES` | `0` | فترة المزامنة التلقائية للأجهزة (0 = معطّلة) |
| `HR_ADMIN_USERNAME` / `HR_ADMIN_PASSWORD` | `admin` / `admin123` | حساب مدير النظام الأول |

## للنشر في بيئة إنتاج

- شغّل خلف Nginx مع HTTPS، واضبط `HR_SECRET_KEY` و`HR_ADMIN_PASSWORD` من متغيرات البيئة.
- انسخ مجلد `data/` احتياطياً دورياً (القاعدة والمرفقات)، أو انتقل إلى PostgreSQL عبر `HR_DATABASE_URL`.
- اجعل الخادم داخل الشبكة التي تصلها أجهزة البصمة، أو اربطها عبر VPN.
