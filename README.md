# نظام الموارد البشرية — الحضور والانصراف والإجازات (متكامل مع بصمة ZKTeco)

نظام كامل يعمل فعلياً: خادم **FastAPI + SQLite** وواجهة عربية (RTL) بدون أي أطر عمل خارجية،
مع تكامل حقيقي مع أجهزة البصمة **ZKTeco** بطريقتين: السحب المباشر عبر المنفذ `4370`،
والدفع اللحظي عبر بروتوكول **ADMS/iclock**.

## المزايا

- **الحضور والانصراف**: استيراد البصمات من الأجهزة، احتساب الحضور والتأخير والخروج المبكر
  والوقت الإضافي وساعات العمل، ودعم الورديات الليلية التي تعبر منتصف الليل.
- **الورديات**: أوقات دوام، دقائق سماح للدخول والخروج، استراحة، وأيام عمل لكل وردية.
- **الإجازات**: أنواع إجازات قابلة للتخصيص، أرصدة سنوية، احتساب الأيام مع استثناء العطل
  الأسبوعية والرسمية، دورة اعتماد (تقديم ← اعتماد/رفض ← إلغاء مع إرجاع الرصيد)، ومرفقات.
- **العطل الرسمية** وتأثيرها التلقائي على كشوف الحضور واحتساب الإجازات.
- **الصلاحيات**: مدير نظام / موارد بشرية / مدير إدارة (يرى ويعتمد فريقه) / موظف (يرى نفسه فقط).
  واجهة الموظف مختصرة عمداً: لوحة مؤشراته الشخصية، حضوره وبصماته، «إجازاتي» (رصيده وطلباته
  وتقديم طلب جديد)، مخالفاته، قسائم رواتبه، ووثائقه — بلا كشوف الآخرين ولا أجهزة البصمة.
- **التقارير**: لوحة مؤشرات، كشف يومي، كشف موظف لفترة، ملخص شهري، تقرير استثناءات،
  وتصدير CSV لكل ما سبق (يفتح مباشرة في Excel بترميز UTF-8).
- **إدارة الأجهزة**: اختبار الاتصال، مزامنة يدوية أو تلقائية، قراءة مستخدمي الجهاز واستيرادهم
  كموظفين، إرسال موظف إلى الجهاز، ضبط ساعة الجهاز، ومسح سجلاته بعد الاستيراد.
- **الحضور الذاتي من التطبيق مقيّداً بالموقع (Geofencing)**: الموظف يسجّل حضوره وانصرافه من
  جواله، ولا تُقبل البصمة إلا إذا كان داخل نطاق موقع عمل معتمد.
- **بصمة يدوية**: إدخال يدوي من الموارد البشرية عند نسيان الموظف البصم.
- **المخالفات والجزاءات**: أنواع مخالفات بسلّم جزاءات تصاعدي حسب التكرار (إنذار ← خصم نسبة من
  أجر يوم ← خصم أيام ← إيقاف/فصل)، مع إقرار الموظف أو تظلّمه، واعتماد الموارد البشرية،
  وخصم تلقائي في مسير الرواتب.
- **مسير الرواتب**: احتساب شهري من الحضور والإجازات والمخالفات (خصم غياب وتأخير وإجازات بلا راتب
  وخصومات المخالفات + بدل العمل الإضافي)، مع تعديلات يدوية واعتماد وقسائم للموظفين وتصدير CSV.
- **الإشعارات**: داخل النظام (جرس بعدّاد) + بريد إلكتروني اختياري + ويب هوك لأي بوابة واتساب/تلجرام.
- **وثائق الموظفين**: إقامة وجواز وعقد وغيرها مع تنبيهات قبل الانتهاء.
- **استيراد جماعي** للموظفين من Excel أو CSV بقالب جاهز.
- **سجل تدقيق** لكل إجراء حسّاس (من فعل ماذا ومتى).
- **ربط جوجل شيت**: كل بصمة وإجازة ومخالفة وقسيمة راتب تنزل تلقائياً في ملف Google Sheets
  عبر Apps Script — بدون حساب Google Cloud ولا مفاتيح، مع صندوق إرسال يعيد المحاولة عند انقطاع الشبكة.
- **نسخ احتياطي**: زر تنزيل نسخة كاملة (قاعدة البيانات + المرفقات) من داخل النظام،
  ورفع تلقائي يومي إلى جوجل درايف عبر rclone.
- **تطبيق قابل للتثبيت (PWA)**: يعمل كأيقونة على جوال الموظف مع أيقونة ومظهر تطبيق مستقل.

## التشغيل السريع

```bash
git clone <رابط المستودع> && cd 123
./run.sh --demo          # يثبّت المتطلبات، ينشئ القاعدة، ويعبّئ بيانات تجريبية
# أو بدون بيانات تجريبية:
./run.sh
```

ثم افتح: <http://localhost:8000>  — وتوثيق الـ API التفاعلي على `/docs`.

|---|---|---|
| `admin` | `admin123` | مدير النظام (يُنشأ دائماً عند أول تشغيل) |

## ربط جهاز البصمة ZKTeco

يدعم النظام الأجهزة التي تتكلم بروتوكول ZKTeco القياسي (iClock، K40، F18، MB360، uFace،
SpeedFace وغيرها). **شرط أساسي:** رقم الموظف في النظام = رقم المستخدم (PIN) في الجهاز.

### 1) وضع السحب (Pull) — الخادم يتصل بالجهاز

1. من الجهاز: `Comm ← Ethernet` واضبط عنوان IP ثابتاً (مثال `192.168.1.201`).
2. تأكد أن المنفذ `4370` مفتوح وأن الخادم في نفس الشبكة (أو يصل إليها عبر VPN).
3. في النظام: **أجهزة البصمة ← إضافة جهاز** ← الوضع «سحب» + IP + المنفذ + كلمة مرور الاتصال
   (Comm Key، افتراضياً `0`).
4. اضغط **اختبار** للتأكد من الاتصال، ثم **مزامنة** لسحب البصمات.
5. للمزامنة التلقائية: `HR_AUTO_SYNC_MINUTES=10` قبل تشغيل الخادم.

### 2) وضع الدفع (Push / ADMS) — الجهاز يرسل البصمة لحظياً

1. من الجهاز: `Comm ← Cloud Server / ADMS`.
2. `Server Address` = عنوان هذا الخادم، `Server Port` = منفذ التطبيق (`8000` افتراضياً).
3. احفظ وأعد تشغيل الجهاز؛ سيبدأ الاتصال بالمسار `/iclock/` وسيظهر تلقائياً في قائمة الأجهزة
   بعد أول اتصال (يمكنك بعدها إعادة تسميته وتحديد موقعه).

المسارات المنفَّذة من بروتوكول ADMS:
`GET /iclock/cdata` (المصافحة)، `POST /iclock/cdata?table=ATTLOG` (استقبال البصمات)،
`GET /iclock/getrequest` (سحب الأوامر المعلّقة)، `POST /iclock/devicecmd` (نتيجة الأمر)،
`GET /iclock/ping`.

> هذه المسارات لا تتطلب توكن لأن الأجهزة لا تدعمه؛ التمييز يتم بالرقم التسلسلي (SN).
> شغّل النظام داخل الشبكة الداخلية، ولا تعرّض مسار `/iclock/` للإنترنت مباشرة إلا خلف
> بوابة/جدار ناري يسمح بعناوين أجهزتك فقط.

### 3) الوضع التجريبي

جهاز بوضع «تجريبي» يولّد بصمات واقعية (تأخير/غياب/إضافي) لتجربة النظام كاملاً بدون عتاد.

## الحضور الذاتي من التطبيق مع التحقق من الموقع (Geofencing)

يستطيع الموظف تسجيل حضوره/انصرافه من التطبيق نفسه، **بشرط أن يكون داخل موقع العمل**:

1. **الإعدادات ← مواقع العمل والبصم الذاتي ← إضافة موقع**: أدخل اسم الموقع والنطاق المسموح
   بالأمتار (افتراضياً 150 م). اضغط **«📍 التقاط موقعي الحالي»** وأنت داخل المقر لتعبئة
   الإحداثيات تلقائياً، أو انسخها من خرائط Google (ضغط مطوّل على المكان).
2. اختيارياً: اربط كل موظف بموقع محدد من بطاقة الموظف (حقل «موقع العمل»). الموظف غير المرتبط
   بموقع يُقبل بصمه من أي موقع معتمد؛ والمرتبط بموقع لا يُقبل منه إلا من ذلك الموقع.
3. الموظف يفتح النظام على جواله ← **لوحة المؤشرات ← «تسجيل حضور / انصراف»**، فيطلب المتصفح
   إذن الموقع، ويتحقق الخادم من المسافة قبل قبول البصمة. زر **«التحقق من موقعي»** يعرض
   المسافة الحالية قبل التسجيل.

**ما الذي يرفضه النظام؟** البصم خارج النطاق (مع ذكر أقرب موقع والمسافة)، أو بدون إذن الموقع،
أو بدقة تحديد ضعيفة تتجاوز الحد المسموح (افتراضياً 150 م).

**ما الذي يُحفظ مع كل بصمة ذاتية؟** الإحداثيات، دقة التحديد، الموقع المطابق، والمسافة عنه —
وتظهر في «سجل البصمات» مع رابط لعرض النقطة على الخريطة.

**الإعدادات المتاحة** (الإعدادات ← مواقع العمل والبصم الذاتي):

| الإعداد | الوصف |
|---|---|
| السماح بالبصم من التطبيق | تعطيل/تفعيل الميزة كلياً |
| إلزام التواجد داخل موقع العمل | عند تعطيله يُقبل البصم من أي مكان (يبقى الموقع مسجلاً للمراجعة) |
| أقصى هامش خطأ للموقع | الحد الأعلى المقبول لدقة GPS بالأمتار |

> **متطلب تقني:** متصفحات الجوال لا تمنح صلاحية الموقع إلا عبر **HTTPS** (أو `localhost` أثناء
> التجربة)، لذا شغّل النظام خلف Nginx بشهادة SSL قبل اعتماد هذه الميزة على أجهزة الموظفين.

> **حدود الميزة بصراحة:** إحداثيات المتصفح يمكن تزييفها بتطبيقات Mock Location على أجهزة
> مُروَّتة. لذلك يبقى جهاز البصمة هو المصدر الأدق، ويُنصح باستخدام البصم الذاتي للمواقع
> الميدانية أو العمل خارج المقر، مع الاعتماد على تخزين الإحداثيات والمسافة لمراجعة أي حالة
> مشبوهة. الحد الأدنى لدقة التحديد يمنع أغلب الحالات العشوائية غير المتعمدة.

## المخالفات والجزاءات

نموذج مبني على جدول المخالفات والجزاءات في لائحة تنظيم العمل:

1. **الإعدادات ← المخالفات والجزاءات**: عشرة أنواع جاهزة (عدم الالتزام بالزي، النظافة، **عدم التواجد
   في المكان المخصص**، مغادرة الموقع، معدات السلامة، التدخين، الجوال، سوء التعامل، رفض التعليمات،
   إتلاف الممتلكات) — كلها قابلة للتعديل، ويجب مطابقتها للائحة المعتمدة لدى منشأتك.
2. لكل نوع **سلّم جزاءات من أربع درجات** حسب التكرار: المخالفة الأولى، الثانية، الثالثة، الرابعة فأكثر.
   الجزاء إما إنذار، أو خصم نسبة من أجر يوم، أو خصم أيام، أو إيقاف بدون أجر، أو الفصل.
3. عند التسجيل يحسب النظام **رقم التكرار تلقائياً** خلال المدة النظامية (افتراضياً 180 يوماً، بعدها
   تُمحى المخالفة من سجل التكرار)، ويعرض الجزاء وقيمة الخصم بالريال قبل الحفظ.
4. المدير أو الموارد البشرية يسجّل المخالفة (مع إمكانية إرفاق مستند وتوثيق الموقع الجغرافي للرصد)،
   فيصل **إشعار فوري للموظف**، وله أن **يقرّ بالاطلاع** أو **يقدّم تظلّماً** يصل للموارد البشرية.
5. عند **اعتماد** المخالفة يُخصم مبلغ الجزاء تلقائياً في مسير رواتب الشهر الذي وقعت فيه.

## مسير الرواتب

يُحتسب من بيانات الحضور الفعلية: خصم الغياب (أجر يوم لكل يوم غياب)، خصم التأخير (بمقدار زمن التأخير،
وقابل للتعطيل)، خصم الإجازات بدون راتب، خصم المخالفات المعتمدة، وبدل العمل الإضافي (أجر الساعة × 1.5
افتراضياً وفق نظام العمل). القواعد كلها قابلة للضبط من **الإعدادات ← قواعد الرواتب**.

الأيام التي **لم تحن بعد** في الشهر الجاري لا تُحتسب غياباً ولا تُخصم.

### الغياب بدون إذن مقابل الغياب بإذن

| الحالة | كيف تُسجَّل | الخصم |
| --- | --- | --- |
| غياب **بدون إذن** | يوم عمل بلا بصمة ولا إجازة | **أجر يومين** عن اليوم الواحد (المعامل الافتراضي 2) |
| غياب **بإذن** بدون راتب | إجازة من نوع «إجازة بدون راتب» معتمدة | أجر يوم واحد |
| غياب **بإذن** مدفوع | إجازة سنوية/اضطرارية/مرضية معتمدة | لا خصم |

معامل خصم الغياب يُضبط من **الإعدادات ← قواعد الرواتب ← خصم يوم الغياب بدون إذن (بالأيام)**،
ويقبل من 0 إلى 3. الأجر المخصوم يُحتسب من الراتب الكامل أو الأساسي حسب «أساس احتساب الخصم» أعلاه.

> تنبيه نظامي: الخصم الزائد عن أجر أيام الغياب يُعدّ جزاءً تأديبياً، فيجب أن يكون منصوصاً عليه في
> لائحة تنظيم العمل المعتمدة للمنشأة وفي حدود ما تجيزه المادة (المخالفات والجزاءات) من نظام العمل.

### الراتب الأساسي والبدلات

لكل موظف حقلان: **الراتب الأساسي** و**البدلات** (سكن، مواصلات… كمبلغ شهري واحد)، وإجمالي الراتب =
الأساسي + البدلات. القسيمة تعرض العمودين وتضيفهما معاً إلى الصافي.

**أساس احتساب الخصم وأجر اليوم** يُضبط من **الإعدادات ← قواعد الرواتب**:

| الخيار | أجر اليوم | متى تختاره |
| --- | --- | --- |
| الأساسي + البدلات (افتراضي) | الإجمالي ÷ أيام الشهر | حين يكون الأجر المتفق عليه هو الإجمالي |
| الأساسي فقط | الأساسي ÷ أيام الشهر | حين تكون البدلات غير خاضعة للخصم |

ونفس الأساس يُستخدم في احتساب جزاءات المخالفات (خصم يوم أو نسبة من أجر يوم).

### استيراد كشف الرواتب والفترات

قالب الاستيراد يحتوي عمودَي **الوردية** و**البدلات**، فيمكن رفع كشف الموظفين كاملاً دفعة واحدة موزعاً
على الفترات. يوجد ملف جاهز كمثال: `deploy/samples/roster_mara_lounge.csv` (فترة صباحية وفترة مسائية،
مع المسمى الوظيفي والأساسي والبدل لكل موظف).

- عمود **الإدارة** يُستخدم للفترة (الفترة الصباحية / الفترة المسائية) ليظهر التجميع في التقارير.
- عمود **الوردية** يجب أن يطابق اسم وردية معرّفة مسبقاً (`الوردية الصباحية`، `الوردية المسائية`)
  وإلا استُورد الموظف بدون وردية مع تنبيه في تقرير الاستيراد.
- بعد الرفع: عدّل أوقات كل وردية وأيام عملها من **الموظفون ← الورديات**، وغيّر أرقام الموظفين
  لتطابق أرقامهم في جهاز البصمة.

## تسجيل دخول الموظفين

يقبل حقل الدخول **اسم المستخدم أو رقم جوال الموظف** المسجّل في ملفه، بأي صيغة معتادة
(`0501234567`، `+966501234567`، `966501234567`، أو بمسافات). كلمة المرور مطلوبة في الحالتين.

- الرقم يُطابَق بعد توحيد صيغته، فلا يهم شكل الإدخال.
- إذا كان الرقم مسجّلاً لأكثر من موظف، يُرفض الدخول به (لا تخمين) ويبقى اسم المستخدم صالحاً.
- الحساب الموقوف لا يدخل بأي منهما.

## السلف على الراتب

تسجّل الموارد البشرية سلفة الموظف بمبلغها وقسطها الشهري وشهر بداية الخصم، فيتكفّل النظام بالباقي:

- الأقساط محسوبة حسابياً من (المبلغ ÷ القسط)، وآخر قسط يأخذ الباقي — مثال: ١٢٠٠ ريال بقسط ٣٠٠ = ٤ أقساط.
- القسط يُخصم تلقائياً في مسير الرواتب في شهره فقط، **وإعادة احتساب المسير لا تُكرّر الخصم**.
- الصفحة تعرض لكل سلفة: المسدَّد، المتبقي، عدد الأقساط، وشريط تقدّم.
- «إلغاء» يوقف الخصم من الشهر التالي، و«تسديد كامل» يقفل السلفة، والحذف ممنوع إذا خُصم قسط
  منها في مسير معتمد.
- الموظف يرى سلفه فقط، وتظهر في قسيمة راتبه بعمود «قسط السلفة».

## تنبيه الغياب والتأخير

مهمة يومية تفحص الحضور بعد بداية وردية كل موظف بمدة قابلة للضبط (٦٠ دقيقة افتراضياً)، وترسل
تنبيهاً واحداً يومياً إلى الموارد البشرية ومدير الإدارة يحوي: **من لم يبصم** و**من تأخر وكم دقيقة**،
وتُنبّه الموظف نفسه أيضاً (قابل للإيقاف). الضبط من **الإعدادات ← التنبيهات وإشعارات الجوال**،
وفيها زر «إرسال التنبيه الآن» للفحص الفوري.

## إشعارات الجوال (Web Push)

يصل الإشعار بنغمة الجهاز حتى والتطبيق مغلق، بلا حساب خارجي ولا خدمة مدفوعة:

1. مفاتيح VAPID تُولَّد تلقائياً عند أول تشغيل وتُحفظ في إعدادات النظام.
2. كل مستخدم يفعّلها على جهازه من **حسابي ← إشعارات الجوال** (زر تفعيل + زر إشعار تجريبي).
3. كل إشعار داخل النظام (إجازة، مخالفة، وثيقة، سلفة، غياب) يُرسَل تلقائياً إلى أجهزة المستخدم.
4. الاشتراكات المنتهية تُحذف تلقائياً عند أول محاولة إرسال فاشلة.

**متطلبات:** HTTPS (متوفر عبر Let's Encrypt في سكربت التثبيت)، وعلى الآيفون يجب إضافة النظام
إلى الشاشة الرئيسية أولاً (iOS 16.4 فأحدث). التفعيل العام من **الإعدادات ← التنبيهات وإشعارات الجوال**.

## ربط جوجل شيت (بدون تعقيد)

يستطيع النظام إنزال بياناته في ملف Google Sheets تلقائياً: **البصمات** فور تسجيلها، **ملخص
الحضور اليومي**، **الإجازات**، **المخالفات المعتمدة**، و**قسائم الرواتب** بعد الاعتماد — كل نوع
في ورقة مستقلة بعناوين عربية.

**الإعداد مرة واحدة (٥ خطوات، بلا حساب Google Cloud ولا مفاتيح JSON):**

1. أنشئ ملف Google Sheets جديداً.
2. **الإضافات (Extensions) ← Apps Script**.
3. احذف الكود الموجود والصق محتوى [`deploy/google_apps_script.gs`](deploy/google_apps_script.gs).
4. غيّر `SECRET` في أول السكربت إلى كلمة سر، ثم **Deploy ← New deployment ← Web app** مع
   `Execute as: Me` و`Who has access: Anyone`.
5. في النظام: **الإعدادات ← ربط جوجل شيت** — الصق الرابط (ينتهي بـ `/exec`) وكلمة السر نفسها،
   واختر البيانات المطلوبة، ثم **اختبار الاتصال**.

**لماذا هذه الطريقة؟** لا تحتاج مشروعاً في Google Cloud ولا حساب خدمة ولا صلاحيات OAuth؛ السكربت
يعمل داخل ملفك بصلاحيتك أنت، ويرفض أي طلب لا يحمل كلمة السر.

**الموثوقية:** كل دفعة تُحفظ في صندوق إرسال داخل قاعدة البيانات قبل إرسالها، فإن انقطعت الشبكة
أو تعطّل جوجل تُعاد المحاولة تلقائياً (حتى ١٢ محاولة) ولا يضيع أي صف. تظهر الحالة في نفس الشاشة:
المعلّق، المُرسل اليوم، الفاشل، وآخر خطأ. وزر **إعادة مزامنة فترة كاملة** يعيد بناء أي ورقة من الصفر.

## قواعد الاحتساب

- **الحضور** = أول بصمة في نافذة اليوم، **الانصراف** = آخر بصمة (الورديات الليلية تمتد لليوم التالي).
- **تأخير** = فارق الدخول عن بداية الوردية إذا تجاوز دقائق السماح (يُحتسب من بداية الوردية).
- **خروج مبكر** = فارق الانصراف قبل نهاية الوردية إذا تجاوز دقائق السماح.
- **وقت إضافي** = ما بعد نهاية الوردية إذا تجاوز السماح، والعمل في يوم راحة يُحتسب كاملاً إضافياً.
- **حالات اليوم**: حاضر / متأخر / انصراف ناقص (بصمة واحدة) / إجازة معتمدة / عطلة رسمية /
  راحة أسبوعية / غياب.
- إعادة الاحتساب تلقائية عند: استيراد بصمات، إدخال يدوي، اعتماد أو إلغاء إجازة، تعديل العطل.

## الواجهة والتصميم

واجهة عربية (RTL) بنظام تصميم موحّد داخل `frontend/styles.css` — بلا مكتبات خارجية ولا رسوم ثقيلة،
فحجم الواجهة كلها ملفّان (CSS + JS) وتعمل بسرعة على الجوال:

- **قائمة جانبية مجمّعة** (عام / الحضور / الإجازات / شؤون الموظفين / الإدارة) قابلة للتصغير إلى أيقونات،
  وتتحوّل إلى درج منزلق على الجوال.
- **لوحة مؤشرات**: بطاقات بأيقونات وألوان حالة، إجراءات سريعة، رسم أعمدة لآخر ٧ أيام،
  ورسم دائري (SVG) لتوزيع الموظفين على الإدارات. للموظف: مؤشرات شخصية فقط.
- **الموظفون**: عرض بطاقات أو جدول، بصورة رمزية بالأحرف الأولى، والحالة، ومدة الخدمة.
- **ملف الموظف**: تبويبات (نظرة عامة، الحضور، الإجازات، الراتب، المخالفات، الوثائق، الجدول الزمني)،
  مع أشرطة تقدّم لنسبة الحضور ورصيد الإجازة وفترة التجربة ومدة العقد المتبقية (من وثيقة العقد).
- **تقويم حضور شهري** ملوّن حسب الحالة، وبطاقات لطلبات الإجازة، وملخص لمسير الرواتب.
- **مركز التنبيهات**: فلاتر حسب النوع (وثائق / إجازات / مخالفات / رواتب) وتعليم الكل كمقروء.
- **تفاصيل**: هياكل تحميل (Skeleton)، تنبيهات Toast بأيقونات، حركات ظهور خفيفة تحترم
  `prefers-reduced-motion`، وتجاوب كامل على الجوال والتابلت.

ملاحظة: صور الموظفين تُعرض كأحرف أولى ملوّنة (لا يخزّن النظام صوراً)، و«الإنذارات» تُقرأ من
سجل المخالفات، و«العقد» من وثيقة نوعها «عقد» ذات تاريخ انتهاء.

## بنية المشروع

```
backend/app/
  main.py            نقطة التشغيل وتجميع المسارات والمزامنة التلقائية
  config.py          الإعدادات من متغيرات البيئة
  models.py          نماذج قاعدة البيانات
  schemas.py         مخططات الإدخال/الإخراج
  security.py        JWT، تجزئة كلمات المرور، والصلاحيات
  seed.py            تهيئة الجداول والحساب الأول والبيانات التجريبية
  migrate.py         إضافة الأعمدة الجديدة إلى قواعد بيانات قائمة
  routers/           auth, users, employees, attendance, leaves, devices, sites, violations,
                     payroll, hr_extra (إشعارات/تدقيق/وثائق/استيراد), reports, iclock
  services/          attendance (الاحتساب)، leave (الأرصدة والاعتماد)، zk_service (المزامنة)،
                     geo (التحقق الجغرافي)، violations (سلّم الجزاءات)، payroll (المسير)،
                     notifications (الإشعارات)، audit (سجل التدقيق)، settings_store (الإعدادات)
  zk/driver.py       طبقة بروتوكول ZKTeco (pyzk) + مولّد البيانات التجريبية
frontend/            واجهة عربية RTL (HTML/CSS/JS بدون أطر عمل) + manifest و service worker للتثبيت كتطبيق
backend/tests/       اختبارات شاملة للمسارات وقواعد الاحتساب
```

## متغيرات البيئة

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `HR_DATABASE_URL` | `sqlite:///data/hr.db` | رابط قاعدة البيانات — SQLite افتراضياً، ويدعم PostgreSQL (مُختبَر) عبر `postgresql+psycopg://...` |
| `HR_DATA_DIR` | `./data` | مجلد البيانات والمرفقات |
| `HR_SECRET_KEY` | يُولَّد تلقائياً | مفتاح توقيع التوكن |
| `HR_TOKEN_MINUTES` | `720` | مدة صلاحية الجلسة بالدقائق |
| `HR_TIMEZONE` | `Asia/Riyadh` | المنطقة الزمنية |
| `HR_AUTO_SYNC_MINUTES` | `0` | فترة المزامنة التلقائية للأجهزة (0 = معطّلة) |
| `HR_ADMIN_USERNAME` / `HR_ADMIN_PASSWORD` | `admin` / `admin123` | حساب مدير النظام الأول |
| `HR_SMTP_HOST` / `HR_SMTP_PORT` / `HR_SMTP_USER` / `HR_SMTP_PASSWORD` | فارغ | إشعارات البريد (اختياري) |
| `HR_WEBHOOK_URL` | فارغ | ويب هوك للإشعارات (واتساب/تلجرام عبر بوابة أو n8n) |

## النشر والاستضافة

راجع **[DEPLOY.md](DEPLOY.md)** — دليل كامل لخيارات الاستضافة (خادم سحابي، خادم داخل الشركة،
أو هجين) وأيها يناسب أجهزتك، مع ملفات جاهزة:

| الملف | الغرض |
|---|---|
| `deploy/install-ubuntu.sh` | تثبيت كامل بأمر واحد على Ubuntu (خدمة + Nginx + شهادة SSL) |
| `deploy/nginx.conf` | وسيط عكسي: HTTPS للموظفين وHTTP لمسار أجهزة البصمة `/iclock/` |
| `deploy/hr.service` | خدمة systemd تعمل تلقائياً عند الإقلاع |
| `Dockerfile` + `docker-compose.yml` | تشغيل بالحاويات |

أهم نقطتين: **HTTPS إلزامي** لعمل تحديد الموقع على الجوالات، و**موقع الخادم** يعتمد على وضع
أجهزة البصمة (السحب يتطلب خادماً داخل شبكة الأجهزة، والدفع يعمل مع أي خادم سحابي).
