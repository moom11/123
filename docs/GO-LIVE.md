# التشغيل اليوم

من خادم فارغ إلى مطعم يعمل. المسار كله أدناه، وما لا أستطيع فعله بدلاً عنك مذكور صراحةً.

---

## 1. خادم — 10 دقائق

أي VPS بأوبنتو 22 أو 24. الأرخص يكفي لفرع واحد:

| المزوّد | الخطة | السعر |
|---|---|---|
| Hetzner CX22 | 2 vCPU / 4GB | ~4 يورو |
| Contabo VPS S | 4 vCPU / 8GB | ~6 يورو |
| DigitalOcean | 2GB | 12 دولار |

اختر منطقة قريبة (فرانكفورت أو البحرين). سجّل عنوان IP.

## 2. نطاق — 10 دقائق

وجّه نطاقاً (أو نطاقاً فرعياً مثل `pos.yourdomain.com`) إلى عنوان الخادم بسجل `A`.

> **HTTPS ليس ترفاً هنا.** بدونه يمنع المتصفح التحديث المباشر من صفحة آمنة —
> وهذا بالضبط سبب شارة «غير متصل» الحمراء التي رأيتها على الاستضافة السابقة —
> ولن يُثبَّت التطبيق على الآيباد كتطبيق.

## 3. أمر واحد

```bash
ssh root@<عنوان-الخادم>

DOMAIN=pos.yourdomain.com bash <(curl -fsSL \
  https://raw.githubusercontent.com/moom11/123/claude/mara-lounge-management-system-tlrc2b/scripts/install.sh)
```

يُثبّت Node 22 و PostgreSQL 16 و nginx، ينشئ القاعدة، **يولّد أسراراً حقيقية**،
يبني التطبيق، يطبّق الهجرات، يزرع البيانات، يركّب الخدمة، ويصدر شهادة TLS.

ويضع nginx أمام كل شيء **بأصل واحد** للواجهة والـ API — وهذا ما يجعل `/api`
النسبي يعمل، ويُبقي المقبس على `wss://` بلا أي إعداد. المشكلتان اللتان كسرتا
الاستضافة السابقة تختفيان هنا بحكم البنية، لا بضبطٍ يُنسى.

في النهاية يطبع بيانات الدخول ورموز الأجهزة في `/etc/mara/seed-output.txt`.
**اقرأها، ثم احذف الملف.**

## 4. ما يجب أن تفعله أنت — نصف ساعة

هذه لا يستطيعها أي سكربت، وكل واحدة تمنع الافتتاح فعلاً:

### أ. غيّر كل كلمة مرور ورمز منشور

البذرة تنشئ حسابات بكلمات مرور **مكتوبة في المستودع العام**. افتح شاشة
المستخدمين وغيّرها كلها — الحسابين الإداريين وستة رموز موظفين. الفحص يرفض
الافتتاح ما دامت واحدة منها قائمة، ويتحقق من التجزئة المخزَّنة لا من كلامك.

### ب. فعّل التحقق الثنائي

أول دخول للمالك سيطلبه. امسح الرمز بتطبيق مصادقة واحفظ رموز الاسترجاع.

### ج. عناوين الطابعات الحقيقية

من شاشة الطابعات: عنوان IP الفعلي لكل طابعة على شبكة المحل، منفذ 9100.
البذرة تضع `192.168.10.1xx` وهي عناوين تجربة.

### د. شغّل وكيل الطباعة على جهاز داخل المحل

```bash
MARA_API_URL=https://pos.yourdomain.com \
MARA_AGENT_TOKEN=<الرمز من seed-output.txt> \
npm --workspace @mara/print-agent start
```

الوكيل **يسحب ولا يُدفَع إليه**، فلا يحتاج الخادم الوصول لشبكة المحل، ولا
الطابعات أن تُعرَّض للإنترنت.

### هـ. اربط الأجهزة

على كل جهاز: افتح الموقع ← شاشة الأجهزة ← الصق رمز الجهاز. **جهاز الكاشير وحده
يقفل الفواتير**، وأجهزة النوادل تأخذ الطلبات فقط.

### و. سجّل الكاشير لدى هيئة الزكاة

شاشة الأجهزة ← «سجّل لدى الهيئة» ← أنشئ CSR ← الصق رمزاً من بوابة «فاتورة».
الباقي تلقائي.

> **هذه النقطة الوحيدة التي قد تؤخر افتتاحك اليوم.** بدون شهادة CSID إنتاجية،
> الفواتير تُختم وتُطبع لكن **الهيئة لا تقبلها**. النظام يُصدرها ويصفّها ولا
> يدّعي أبداً أنها أُبلغت. القرار قرارك، والمخاطرة نظامية لا تقنية.

### ز. أدخل منيوك الحقيقي

```bash
cd /opt/mara
npm --workspace @mara/server run import-menu -- packages/server/data/mara-menu.json
```

هذا منيو مارا الذي استخرجته من ملف FineDine — 115 صنفاً في 16 تصنيفاً.
راجع الأسعار قبل الافتتاح.

## 5. الفحص الأخير

```bash
cd /opt/mara && npm --workspace @mara/server run preflight
```

يرفض الافتتاح على: كلمة مرور منشورة، رمز موظف منشور، أسرار تطوير، طابعة على
عنوان تجربة، فرع بلا رقم ضريبي، كاشير بلا شهادة إنتاجية، سلسلة فواتير منقطعة،
أو فاتورة مضى عليها 24 ساعة دون إبلاغ.

**عالج كل مانع. ثم افتح.**

---

## ما ينقص وأنت تفتح

ليست موانع، لكن اعرفها قبل لا بعد:

- **لا نسخ احتياطي بعد.** أضفه اليوم — نظام يمسك مالاً بلا نسخة احتياطية ليس
  جاهزاً مهما كانت اختباراته:
  ```bash
  echo '0 4 * * * postgres pg_dump mara | gzip > /var/backups/mara-$(date +\%F).sql.gz' \
    | sudo tee /etc/cron.d/mara-backup
  sudo mkdir -p /var/backups && sudo chown postgres /var/backups
  ```
- **واتساب** يحتاج بيانات حساب أعمال في `.env`. بدونه لا تعمل خصومات العملاء ولا
  استبدال النقاط — وبقية النظام يعمل.
- **دفع المنيو إلى منصات التوصيل** يدوي في لوحة كل منصة. الاستقبال يعمل كاملاً.
- **عناوين API منصات التوصيل** تحتاج مطابقة مع وثائق كل منصة عند التعاقد —
  تعديل سطر في محوّلها.

## التحديث لاحقاً

```bash
cd /opt/mara && sudo bash scripts/install.sh
```

نفس الأمر. لا يولّد أسراراً جديدة (توليدها يُخرج كل الأجهزة ويُعطّل التحقق
الثنائي)، ولا يعيد زرع قاعدة فيها بيانات.

## حين يتعطّل شيء

```bash
systemctl status mara        الحالة
journalctl -u mara -f        السجل الحي
curl localhost:4000/health   هل الـ API حي أصلاً
```

`‏/health` يرجع حالة قاعدة البيانات وزمن استجابتها وعدد المتصلين — أسرع طريقة
لمعرفة ما إذا كانت المشكلة في الخادم أم في الشبكة أم في الواجهة.
